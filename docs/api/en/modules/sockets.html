    sockets

    import "sockets"

    talking over the network: TCP and UDP sockets (docs/sockets.md)

    import "sockets" and four modules are yours (thunderc finds this file in lib/thunder next to itself, or name a directory with --module-path):

    tcp connections: listen, accept, connect, and request (one whole exchange) udp single messages (datagrams): open, send, receive, sender socket what every socket can do: send and receive text or bytes, close, timeouts ... host names and addresses: host.address("example.org"), host.name()

    The work is done in C++ (lib/native/sockets/thunder_sockets.cpp), built with the toolchain as the native library thunder_sockets, which sits next to thunderc and thundervm and is copied beside a packaged program automatically.

    A socket is a socket.Socket. Opening one can fail - nobody listens, the port is taken - and then the answer is nothing, and socket.error() says why. A socket is a resource, so "with" closes it for you at the end of the block, however the block ends:

    with connection = tcp.connect("localhost", 7000) if connection != nothing socket.send_line(connection, "hello")

    Passing a socket that is closed already is a mistake in the program and stops it, as a wrong built-in call would.

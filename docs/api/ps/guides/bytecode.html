    د تندر SDK لارښود یوه برخه.

    دا سند د docs/bytecode.md پښتو ژباړه ده. انګلیسي اصل معتبر دی (د لارښوونو بشپړ جدول او د فایل بڼه هلته ده)؛ ژباړه د یوه ژبپوه کتنې ته اړتیا لري.

    thunderc هر پروګرام بایټ کوډ ته اړوي: د یوه ساده سټک-ماشین لارښوونې، چې thundervm یې اجرا کوي. IDE کې د «بایټ کوډ»، «بائنري» او VM پاڼې همدا ښيي.

    ۱. د ماشین انځور#

    مجازي ماشین سټک-ماشین دی: لارښوونې ارزښتونه پر یوه سټک ږدي او ترې اخلي.

    کرښه چاپ(۲ + ۳ * ۴)

بایټ کوډ: CONST 0            ; ۲ کېږده            سټک: [۲]
          CONST 1            ; ۳ کېږده            سټک: [۲، ۳]
          CONST 2            ; ۴ کېږده            سټک: [۲، ۳، ۴]
          MUL                ; ۳ * ۴              سټک: [۲، ۱۲]
          ADD                ; ۲ + ۱۲             سټک: [۱۴]
          CALL_BUILTIN 1 1   ; کرښه چاپ(۱۴)       سټک: []

    ارزښتونه#

    د اجرا ارزښتونه: عدد، منطقي، متن، لړۍ، جوړښت، ټاپل، نقشه او د دندې ارزښت. لړۍ، جوړښتونه او نقشې ماخذونه دي (د ماخذ شمېرنه یې پاکوي؛ د ډولونو سیسټم دورونه ناشوني کوي). ټاپلونه نه بدلېږي او EQ یې توکی په توکی پرتله کوي.

    دندې، چوکاټونه او ځایي ځایونه#

    هره دنده خپل کوډ لري. بلنه یو چوکاټ (frame) ږدي: دلیلونه د بلل شوې دندې لومړي ځایي ځایونه (slots) کېږي، ورپسې نور ځایي متغیرونه، او له هغو پورته یې لنډمهالي عملوندونه. «راګرځه» چوکاټ لیرې کوي او پایله بلونکي ته ږدي. د سر کچې کوډ په <main> (<اصلي>) کې دی، چې لومړی چلېږي او که اصلي() تعریف وي، په پای کې یې بولي. نړیوال متغیرونه (د سر کچې متغیرونه، او د ټولګي متغیرونه) په بېل جدول کې دي او LOAD_GLOBAL / STORE_GLOBAL کاروي.

    نومونه. هره دنده، جوړښت، ګڼنه او نړیوال متغیر هماغه نوم ساتي چې پرې اعلان شوی، او د یوه ټولګي غړی له خپل ټولګي سره نومول کېږي: هندسه.مساحت، هندسه.ټکی، هندسه.شمېر. همدا بشپړ نومونه د .thc فایل په جدولونو کې دي، او لېست (CALL 1 ; هندسه.مساحت)، --trace، ډیبګر او د اجرا د تېروتنې د بلنو ډېرۍ همدا ښيي. له ټولګو څخه په بایټ کوډ کې یوازې همدا پاتې کېږي: د ټولګو لپاره هېڅ لارښوونه نشته، او د هندسه.مساحت بلل هومره بیه لري لکه د سر کچې مساحت. د یوه ټولګي دننۍ دندې هم همداسې نومول کېږي - CALL_BUILTIN 77 1 ; math.sqrt (لېست د دننیو دندو انګلیسي نومونه ښيي).

    ۲. د لارښوونو ټولګه#

    هره لارښوونه ۱-بایټ کوډ + کوچني-اختر (little-endian) عملوندونه ده. بشپړ جدول (۶۱ لارښوونې) د انګلیسي سند ۲ برخه کې دی؛ ډلې یې:

    ډله لارښوونې
    ثابت/منطقيCONST، TRUE، FALSE، POP، DUP، DUP2 (د ل[ش] += ا لپاره)
    متغیرونهLOAD_LOCAL، STORE_LOCAL، LOAD_GLOBAL، STORE_GLOBAL
    حسابADD، SUB، MUL، DIV، MOD، NEG (اوښتل او په صفر وېش = د اجرا تېروتنې). دا لارښوونې پر بشپړو عددونو او اعشاري شمېرو یو شان کار کوي: د سټک د ارزښتونو ډول ګوري.
    اړونهINT_TO_FLOAT (بشپړ عدد اعشاري کوي؛ هلته چې ډول کتونکي پراخه کړې ده)
    متن/پرتلهCONCAT، EQ، NE، LT، LE، GT، GE، NOT
    ورټوپونهJUMP، JUMP_IF_FALSE
    بلنېCALL، CALL_BUILTIN، RETURN، RETURN_VOID
    لړۍ/نقشېMAKE_ARRAY، INDEX_GET، INDEX_SET، MAKE_TUPLE، TUPLE_GET، MAKE_MAP
    جوړښتونهNEW_STRUCT، GET_FIELD، SET_FIELD، CALL_METHOD (د دلیلونو لاندې د جوړښت نومول شوې دنده بولي - د برسېر له لارې متحرک ورټوپ (dynamic dispatch)؛ اخیستونکی د دندې لومړی ځایي ځای کېږي؛ پر هېڅ د اجرا تېروتنه R036. که همنومې برخه د دندې ارزښت ولري، هغه لکه CALL_VALUE بلل کېږي.)
    د دندو ارزښتونهFUNC_REF (د دندې ارزښت ږدي؛ 65535 = «بې دندې»)، CALL_VALUE
    صندوقونه او closureونهNEW_BOX (ارزښت نوي صندوق ته وړي - هغه متغیر چې د دندې کوم ارزښت یې نیسي په یوه کې ژوند کوي)، BOX_GET (صندوق د دنني ارزښت په ځای کوي)، BOX_SET (ارزښت په صندوق کې ږدي)، MAKE_CLOSURE (شمېر صندوقونه اخلي او داسې د دندې ارزښت ږدي چې وړي یې - closure)، LOAD_CAPTURE (د چلېدونکي closure یو صندوق ږدي؛ نیول شوی متغیر په BOX_GET لوستل او په BOX_SET لیکل کېږي)
    بیټي عملګرBIT_AND، BIT_OR، BIT_XOR، SHL، SHR (شمېر ۰..۶۳)، BIT_NOT
    بایټونهBYTE_TO_INT (بایټ عدد ته پراخوي)، INT_TO_BYTE (ټیټ ۸ بیټونه ساتي)
    ګڼنېENUM_CONST (ګڼنه، غړی: ګرافیک.رنګونه.سور)، ENUM_FROM (له عدد یا متن څخه غړی؛ R034/R035)، ENUM_VALUES (د ټولو غړو لړۍ)

    CALL_BUILTIN دننۍ دنده د شمېرې له مخې بولي (جدول: src/core/builtins.cpp)؛ د بایټ کوډ پاڼه او thunderc --emit asm د هرې دننۍ دندې نوم د شمېرې تر څنګ ښيي، د هغو دننیو دندو لپاره چې په یوه ټولګي کې دي له ټولګي سره (math.sqrt، string.trim، graphics.circle - په پښتو کې ریاضي.جذر، متن.پاک کړه، ګرافیک.دایره). د ګرافیک ټولګی نوې لارښوونې نه غواړي: دندې یې د VM ټاټ بدلوي، او ګرافیک.چوکاټ() یې ګرافیک کوربه ته وړاندې کوي (د ګرافیک لارښود ۸ برخه). پر هر یو/چاڼ کړه/راټول کړه خپله دنده د VM له دننه، لکه CALL_VALUE، بولي.

    ۳. امرونه بایټ کوډ ته#

    که ش (برخه A)، کنه (برخه B):

            <ش>
        JUMP_IF_FALSE else
        <A>
        JUMP end            ; که A تل راګرځي، نه لیکل کېږي
else:   <B>
end:

    ترڅو ش له ننوتې برخې سره:

    start:  <ش>
        JUMP_IF_FALSE end
        <برخه>              ; ودرېږه -> JUMP end، دوام -> JUMP start
        JUMP start
end:

    تکرار پیل، ش، ګام له ننوتې برخې سره:

            <پیل>
start:  <ش>
        JUMP_IF_FALSE end
        <برخه>              ; دوام -> JUMP next
next:   <ګام>
        JUMP start
end:

    ټکی(۱، ۲) د برخو ارزښتونه ږدي او NEW_STRUCT یې جوړوي؛ ټکی(ص: ۲، س: ۱) له اصلي ارزښتونو پیلوي او هره نومول شوې برخه په SET_FIELD ږدي، نو دلیلونه له کیڼه ښي ارزول کېږي.

    الف او ب ورټوپونه کاروي چې ب یوازې د الف له رښتیا وروسته وارزول شي (لنډه لار):

            <الف>
        JUMP_IF_FALSE false
        <ب>
        JUMP end
false:  FALSE
end:

    ۴. د .thc فایل بڼه#

    سرلیک: جادويي "THND"، بڼه-نسخه (۸؛ نسخه ۵ اعشاري ثابتونه زیات کړل، نسخه ۷ د ګڼنو جدول او د بایټ او ګڼنې لارښوونې، نسخه ۸ د جوړښتونو د دندو جدولونه، د نیول شویو شمېر او د صندوق، closure او دندې-بلنې لارښوونې؛ VM د نورو نسخو فایلونه نه مني)، د سرچینې نوم، د ژبې کوډ (en/ps) او د سرچینو فایلونو لړ (پروګرام + راوړل شوي فایلونه). ورپسې: ثابتونه، جوړښتونه (هر یو له برخو وروسته خپل د دندو جدول لري: د غړي نوم + د دندې شاخص، چې CALL_METHOD دنده پکې لټوي)، ګڼنې، عمومي متغیرونه، د دندو جدول (نومونه یې د ټولګو د غړو لپاره بشپړ دي: هندسه.مساحت، ګرافیک.رنګونه) او د هرې دندې کوډ — له خپلې بڼې سره، چې اوس د نیول شویو شمېر هم لري (د دې دندې یو MAKE_CLOSURE څومره صندوقونه وړي) — او له د کرښو جدول سره، چې هره لارښوونه بېرته سرچینې ته (فایل، کرښه، ستن) نقشه کوي — د اجرا تېروتنې او ډیبګر همدا کاروي. د ژبې کوډ ټاکي چې VM ارزښتونه او پیغامونه څنګه ښيي: له پښتو جوړ شوی پروګرام ۴۲، رښتیا او پښتو تېروتنې چاپوي. تفصیلي جدول: انګلیسي سند ۴ برخه. IDE کې «بائنري» پاڼه هره برخه په خپل رنګ ښيي؛ په قومانده کې thunderc --emit hex.

    ۵. خوندیتوب: تایید کوونکی#

    thundervm هېڅکله پر .thc فایل باور نه کوي. له چلولو مخکې تاییدوي: جادويي شمېره او اوږدوالي، هر کوډ پېژندل شوی او هر عملوند په حد کې (ثابتونه، ځایونه، دندې، جوړښتونه، دننۍ دندې...)، هر ورټوپ د لارښوونې پر پیل، او هره دنده په HALT/RETURN/RETURN_VOID/ JUMP پای ته رسېږي. د چلولو پر مهال د عملوندونو ډولونه، د سټک ژوروالی، د بلنو ژوروالی او (اختیاري) د ګامونو حد هم ګوري. ناسم فایل د R010 پیغام راوړي، نه حادثه. ازموینې د جوړ شوي فایل هر بایټ اړوي او په هر اوږدوالي یې پرېکوي.

    ۶. د قوماندې وسایل#

    thunderc program.th                 # جوړول → program.thc
thunderc --lang ps program.th       # پروګرام پښتو دی (یا "# ژبه: ps")
thunderc --translate ps program.th  # پروګرام پښتو ته وژباړه
thunderc --emit all program.th      # توکي، نحوي ونه، نښې، بایټ کوډ، hex هم چاپ کړه
thunderc --json program.th          # هر څه JSON (IDE همدا کاروي)
thunderc -I libs program.th         # راوړل شوي فایلونه په libs/ کې هم ولټوه
thundervm program.thc               # چلول (ولوله() معیاري ننوت لولي)
thundervm program.thc یو دوه        # دلیلونه پروګرام ته (سیسټم.دلیلونه()، راوړه سیسټم)
thundervm --trace program.thc       # هره لارښوونه او سټک ښيه
thundervm --debug program.thc       # د ژوندي ډیبګر لاندې چلول (docs/debugging.md؛ VS Code)
thundervm --stats program.thc       # شمېرنې: ګامونه، بلنې، ژوروالی
thundervm --svg out.svg --max-frames 50 anim.thc   # ګرافیک: تر ۵۰ چوکاټه، انځور وساته

    د وتلو حالت: ۰ بریا (یا د سیسټم.پای ته ورسوه(کوډ) کوډ)، ۱ د اجرا تېروتنه، ۲ ناسم کارول یا ناسم فایل.

    د tools/apidoc.py له لارې د اوزارو د ژبې له معلوماتو، د SDK له خپلو تبصرو او له لارښودونو جوړ شوی. د MIT جواز.

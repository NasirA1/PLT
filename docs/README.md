# The Thunder SDK reference

Everything about programming in Thunder, in reading order. In the IDE these documents are
under **Help**, as pages of the HTML API documentation below, shown in a browser window; on
GitHub the links below work directly. Pashto translations live in [`docs/ps/`](ps/README.md),
and the Pashto interface's Help menu opens the Pashto pages.

## The API documentation (HTML)

The same material as a browsable, searchable HTML5 site - the keywords and types, every
built-in function with its signature, the SDK modules' structs and functions with their
parameters and documentation, the instruction set and these guides - is in
[`docs/api/index.html`](api/index.html), in English and Pashto with a link on every page to
the same page in the other language. It is generated by `tools/apidoc.py` from the compiler's
language information, the SDK's own comments and the documents below (run it after changing
any of them; the test suite checks that it is up to date).

## Learning the language

| Document | What it covers |
| --- | --- |
| [Language reference](language.md) | The whole language: lexical rules (including `0x`/`0b` number notation), types, operators (arithmetic, comparison, logical and bitwise), statements, functions, structs, tuples, maps, modules and the grammar. |
| [Library reference](library.md) | Everything built in: input/output and `format`, text functions, conversions (`to_int`, `hex`, `bin`, ...), arrays, maps, maths, `map`/`filter`/`reduce`, and the `os` module. |
| [Data structures reference](datastructures.md) | Stacks, queues, deques, linked lists, binary search trees, heaps, sets, graphs and tries, generic and written in Thunder itself (`import "datastructures"`). |
| [Algorithms reference](algorithms.md) | The classic sorting, searching and text algorithms (substring search, edit distance, ...), written in Thunder itself (`import "algorithms"`). |
| [Testing reference](testing.md) | A small test framework (`import "testing"`): `test`, `expect_equal` and its companions, the ✓/✗ transcript, running one test by name, and the VS Code Test Explorer. |

## The pieces on disk

| Directory | Contents |
| --- | --- |
| `samples/en/`, `samples/ps/` | The numbered sample programs (only programs live here). |
| `samples/project/` | A multi-file project - entry point, modules and a `thunder.json` - for trying the VS Code extension. |
| `lib/thunder/` | Reusable Thunder modules shipped with the toolchain (`import "sockets"`, `import "datastructures"`, `import "algorithms"`, `import "testing"`). |
| `lib/native/` | Native modules in C++: the demo and the sockets library. |
| `lib/display/` | Display plug-ins in C: text, Win32/GDI and SDL2. |
| `ide/vscode/` | The VS Code extension: highlighting, IntelliSense, tasks and a debugger that steps backwards ([how to install and use it](../ide/vscode/README.md)). |

The development history - every iteration, what changed and why - is in
[`devlog.md`](../devlog.md) at the repository root.

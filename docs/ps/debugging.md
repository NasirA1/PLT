# د تندر د ډیبګ لارښود

څنګه یو پروګرام د چلېدو پر مهال ډیبګ کېږي، او هغه پروتوکول چې د ډیبګر یو مخکښ (front end) یې له
مجازي ماشین سره خبرې کوي. د VS Code توسیع (`ide/vscode`) یو داسې مخکښ دی؛ د Qt IDE ګام په ګام
ډیبګر پر ځای له یوه ثبت څخه کار اخلي (`thundervm --trace-json`، چې په
[د بایټ کوډ او VM لارښود](bytecode.md) کې تشریح شوی). انګلیسي اصل په
[`docs/debugging.md`](../debugging.md) کې دی او هر ځای چې ژباړه نیمګړې وي، اصل باوري دی.

## ۱. د چلېدونکي پروګرام دننه کتلو دوه لارې

| | `thundervm --debug` (ژوندی) | `thundervm --trace-json` (ثبت شوی) |
| --- | --- | --- |
| پروګرام | د ډیبګر لاندې چلېږي او هلته درېږي چې ورته وویل شي | تر پایه چلېږي او هره لارښوونه لیکل کېږي |
| د درېدو ټکي (breakpoints) | پروګرام هغه ځای درولي چې ورته رسېږي؛ شرطونه او د رسېدو شمېر | وروسته، پر ثبت پلي کېږي |
| ګام اخیستل | بلنو ته ننوتل، تر بلنو تېرېدل، له بلنو وتل، او د ساتل شوې تاریخچې له لارې **شاته** تګ | پر ټول ثبت مخکې او شاته |
| متغیرونه | د هر چوکاټ (frame) محلي متغیرونه، نړیوال، د لړۍ توکي او ساحې یوه کچه پر یوه کچه | د چلېدونکي چوکاټ محلي او نړیوال متغیرونه، د متن په بڼه |
| `ولوله()` | له مخکښ پوښتي، چې هغه له کارونکي پوښتي | له مخکې ورکړل شوي متن څخه |
| ګرافیک | د ښودونکي پلګ-ان له لارې کړکۍ (`--display`) | یوازې وروستی انځور |
| کارونکی | د VS Code توسیع | د Qt IDE |

پاتې لارښود د ژوندي ډیبګر په اړه دی.

## ۲. د ناستې پیل

```
thundervm --debug [--history <n>] [--display <name>] [--native-path <dir>] program.thc [arguments...]
```

معیاري ننوت او معیاري وتنه خبرې اترې وړي: په هر لوري کې په هره کرښه کې یو JSON شی. د پروګرام
خپله وتنه معیاري وتنې ته **نه** ځي – د `output` پېښو په بڼه راځي – او `ولوله()` معیاري ننوت
نه لولي – د `input` پېښه لېږي او د `input` امر ته انتظار باسي. (له همدې امله `--canvas` له
`--debug` سره نه منل کېږي؛ ګرافیکي پروګرام د `--display` سره ډیبګ کېږي.) معیاري تېروتنه
(standard error) بدله نه ده.

`--history <n>` وايي چې ډیبګر د شاته تګ لپاره څومره اجرا شوې کرښې په یاد ساتي (تلواله ۱۰۰۰۰؛
`0` هېڅ نه ساتي). هره ننوتنه د بلنو سټک او هر متغیر د متن په بڼه لري، نو حد حافظه محدودوي، نه
وخت.

ناسته د `ready` پېښې سره پیلېږي، بیا ډیبګر **له لومړۍ لارښوونې مخکې درېږي** او د `entry` دلیل
سره `stopped` راپور ورکوي. دا هغه ځای دی چې مخکښ خپل د درېدو ټکي ږدي؛ هغه مخکښ چې دا درېدل
ښودل نه غواړي، ساده `continue` لېږي. هغه د درېدو ټکی چې د دې درېدو پر مهال پر لومړۍ کرښه
کېښودل شي، د پروګرام د دوام پر مهال چلېږي.

کله چې پروګرام پای ته ورسېږي – په عادي ډول، د `سیسټم.پای ته ورسوه()` له لارې، د چلېدو د تېروتنې له امله، یا
ځکه چې مخکښ یې وغوښتل – ډیبګر `exited` لېږي او پروسه پای ته رسېږي. د چلېدو تېروتنه لومړی د
درېدو په بڼه راپور کېږي (دلیل `exception`)، نو هغه حالت چې پروګرام پکې ناکام شو کتل کېدای شي؛
بیا هر ډول د ګام امر پروګرام پای ته پرېږدي.

## ۳. پیغامونه

هر پیغام په خپله کرښه کې یو JSON شی دی.

**غوښتنې** (مخکښ ← ډیبګر) د مخکښ په خوښه یو `seq` او یو `command` لري:

```json
{"seq": 7, "command": "next"}
```

**ځوابونه** د غوښتنې شمېره په `request_seq` کې تکراروي:

```json
{"type": "response", "seq": 12, "request_seq": 7, "command": "next", "success": true, "body": {}}
{"type": "response", "seq": 13, "request_seq": 8, "command": "evaluate", "success": false, "message": "'n * 2' is not a variable here ..."}
```

**پېښې** (ډیبګر ← مخکښ) ناغوښتل شوې دي:

```json
{"type": "event", "seq": 14, "event": "stopped", "reason": "breakpoint", "step": 36, "historic": false,
 "history": {"index": 9, "size": 10}, "function": "factorial", "file": 0, "line": 12, "column": 12}
```

هغه کرښه چې JSON شی نه وي د `error` پېښې سره ځوابېږي او بیا له پامه غورځول کېږي؛ ناپېژندل
شوی امر ناکام ځواب ترلاسه کوي. هغه غوښتنې چې یوازې د حالت پوښتنه کوي (`stackTrace`،
`variables`، `evaluate`، `setBreakpoints`) هر وخت ځوابېږي – پروګرام درېدلی وي، چلېږي (د
لارښوونو تر منځ) یا ننوت ته انتظار باسي؛ د ګام امرونه د چلېدو پر مهال ردېږي.

### پېښې

| پېښه | ساحې | کله |
| --- | --- | --- |
| `ready` | `program` (د سرچینې نوم)، `files` (د سرچینې فایلونه، د `file` د شاخص په ترتیب) | یو ځل، په پیل کې |
| `stopped` | `reason`: `entry`، `breakpoint`، `step`، `pause` یا `exception`؛ `description` او `text` (د تېروتنې پیغام او بشپړ راپور، یا دا چې ولې د درېدو ټکی ناڅاپه وچلېد)؛ `step`؛ `historic`؛ `history` `{index, size}`؛ د دننني چوکاټ `function`، `file`، `line`، `column` | پروګرام ودرېد |
| `continued` | | پروګرام بیا چلېږي |
| `output` | `text` | پروګرام څه ولیکل |
| `input` | | `ولوله()` وبلل شو: د `input` امر سره ځواب ورکړئ |
| `exited` | `ok`، `exit_code`، `aborted`، `steps`، `error` (د چلېدو تېروتنه لکه په `--result-json` کې، یا `null`) | پای |
| `error` | `message` | یوه کرښه چې غوښتنه نه وه |

### امرونه

| امر | دلیلونه | د ځواب بدن |
| --- | --- | --- |
| `setBreakpoints` | `file` (شاخص)، `breakpoints`: `[{line, condition?, hitCondition?}]` – د هغه فایل ټول د درېدو ټکي ځایناستي کوي | `breakpoints`: `[{line, verified, message?}]` په همغه ترتیب؛ هغه د درېدو ټکی چې پر بې کوډه کرښه وي، راتلونکې کوډ لرونکې کرښې ته ځي، یا نه تاییدېږي |
| `continue` | | تر راتلونکي د درېدو ټکي پورې چلېږي |
| `next` | | په همدې دنده یا بلونکې دنده کې تر راتلونکې کرښې پورې چلېږي |
| `stepIn` | | تر راتلونکې کرښې پورې چلېږي، هر ځای چې وي |
| `stepOut` | | تر هغه چلېږي چې اوسنۍ دنده راوګرځي |
| `stepBack` | | له تاریخچې څخه پخوانۍ کرښه ښيي |
| `reverseContinue` | | په تاریخچه کې هغه پخوانۍ کرښه ښيي چې د درېدو ټکی لري، یا تر ټولو لومړۍ یاده کرښه |
| `pause` | | چلېدونکی پروګرام په راتلونکې لارښوونه کې دروي |
| `stackTrace` | | `frames`: `[{index, function, file, line, column}]` دنننی لومړی؛ `historic`؛ `step` |
| `variables` | `frame` (شاخص، تلواله 0)، `scope`: `locals`، `globals`، `stack` (د دننني چوکاټ عملوندونه) یا `execution` (ګام، لارښوونه، ځای)؛ `path` (اختیاري: هغه متغیر، ساحه یا توکی چې منځپانګه یې غوښتل کېږي، لکه `items[1]`) | `variables`: `[{name, value, type, expandable}]`؛ `message` کله چې هېڅ ونه لیکل شول |
| `evaluate` | `expression`، `frame` | `value`، `type`، `expandable` |
| `input` | `text`، یا د ننوت د پای لپاره `end: true` | |
| `terminate`، `disconnect` | | پروګرام پای ته رسوي؛ `exited` ورپسې راځي |

**د فایل شاخصونه.** ځایونه خپل فایل د پروګرام د سرچینو په شاخص نوموي: `0` پخپله پروګرام
دی، بیا هغه فایلونه چې راوړي یې (`راوړه "sockets"`، `راوړه "lib/geometry"`) په هغه ترتیب چې
کمپایلر بار کړي – همغه شمېرنه چې `thunderc --json` راپور ورکوي او د `ready` پېښه یې لیکي.

**د دندو نومونه.** د چوکاټ `function` (په `stopped` او `stackTrace` کې) هغه نوم دی چې کمپایلر
ورکړی: د سر کچې امرونو لپاره `<main>`، د سر کچې دندې لپاره د دندې خپل نوم، او د یوه
[ټولګي](language.md) د غړي لپاره یې **بشپړ نوم** - `هندسه.مساحت`، `ساکټ.کرښه_ولېږه` - لکه
څنګه چې یې د بایټ کوډ لېست، د اجرا د تېروتنې د بلنو ډېرۍ او `د دندې نوم` ښيي. د ټولګي
متغیرونه هم نړیوال دي له بشپړو نومونو سره: د `globals` ساحه یې د `هندسه.شمېر` په بڼه
لیکي. (`evaluate` یې په دې نوم نه مومي: `هندسه.شمېر` د `هندسه` متغیر د `شمېر` ساحې
په توګه لولي. پر ځای یې د `globals` په ساحه کې وګورئ.)

**کرښې.** درېدل تل د یوې کرښې پر لومړۍ لارښوونه *په خپل چوکاټ کې* راپور کېږي، نو د
`متغیر ځواب = دوه_چنده(۲۱)` پر کرښه د درېدو ټکی یو ځل چلېږي، نه بیا کله چې `دوه_چنده` د کرښې
پاتې برخې ته راوګرځي. `stepOut` استثنا ده: سمدستي له بلنې وروسته درېږي، د بلونکي کرښې په منځ
کې، لکه نور ډیبګرونه.

**شرطونه.** د درېدو ټکي `condition` د یوه متغیر (یا د هغه ساحې یا توکي) او یوه ارزښت یا بل
متغیر تر منځ پرتله ده: `n == 2`، `person.born > 1800`، `items[0] != "x"`، `done` (یوازې یو
`بولین`). هغه شرط چې ارزول نه شي، درېدل نه پټوي؛ د `stopped` پېښه دا په `description` کې وايي.
`hitCondition` شمېري چې کرښې ته څو ځله ورسېدل: `3` یا `== 3` (درېیم ځل)، `>= 3`، `> 3`،
`< 3`، `<= 3`، `% 3` (هر درېیم ځل).

**څرګندونې.** `evaluate` همغه ژبه پوهېږي چې شرطونه: یو متغیر، `a.b`، `a[2]`، `a["key"]`،
`a[1].b[0]`، او یوه پرتله. دندې نه بولي او حساب نه کوي. متغیر لومړی په ټاکل شوي چوکاټ کې
لټول کېږي، بیا د نړیوالو تر منځ؛ د دنننۍ بلاک متغیر د همنومه بهرني متغیر پر ځای راځي.

### تاریخچه

هره کرښه چې پروګرام اجرا کوي، (تر `--history` پورې) له خپل د بلنو سټک او متغیرونو سره د متن
په بڼه یادېږي. `stepBack` او `reverseContinue` په دې تاریخچه کې ګرځي؛ د `stopped` پېښه بیا
`historic: true` وايي، `stackTrace`، `variables` او `evaluate` له یاد شوي حالت څخه ځواب ورکوي،
او ارزښتونه نه شي پرانیستل کېدای (`expandable` د `false` وي). له یادې کرښې څخه مخکې ګام
اخیستل په تاریخچه کې تر هغه ګرځي چې ژوندي حالت ته ورسېږي او بیا پروګرام مخکې چلوي؛ `continue`
په تاریخچه کې پر هغو یادو کرښو درېږي چې اوس د درېدو ټکی لري (شرطونه بیا نه ارزول کېږي). وتنه
یو ځل لېږل کېږي، کله چې پېښېږي – هېڅکله بیا، کله چې تاریخچه ښودل کېږي.

## ۵. د اوزارو دننه

ډیبګر `thunder::Debugger` دی (`include/thunder/debugger.hpp`)، یو `VmObserver`: مجازي ماشین یې
له هرې لارښوونې مخکې بولي، او کله چې پروګرام باید هلته ودرېږي، له خپل `DebugChannel` څخه امرونه
لولي تر هغه چې یو یې پروګرام بیا وچلوي. `StreamChannel` پر معیاري ننوت او وتنه چینل دی، چې په
شالید تار کې لولي، نو `pause` د پروګرام د چلېدو پر مهال رارسېدای شي؛ ازموینې ډیبګر د یوه لیکل
شوي (scripted) چینل له لارې چلوي (`tests/cpp/test_debugger.cpp`). په بله ژبه لیکل شوي مخکښ ته
یوازې یوه پروسه، دوه پایپونه او یو JSON کتابتون پکار دي.

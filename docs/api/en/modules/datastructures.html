    import "datastructures"

    the classic data structures, written in Thunder itself (docs/datastructures.md)

    import "datastructures" and every structure below is yours (thunderc finds this file in lib/thunder next to itself, or name a directory with --module-path). Unlike sockets or graphics nothing here is native: this is ordinary Thunder, written to be read - open this file to see how a stack, a queue, a linked list, a binary search tree and a heap really work.

    Every structure is generic: stack.Stack<T> works for any element type T, deduced from what the program does with it - a stack of strings is stack.Stack(items: ["a"]) or "var s: stack.Stack<string> = stack.new()". The tree and the heap compare their elements with <, so their elements are numbers or strings.

    Taking from an empty structure is a mistake in the program and stops it, as a wrong built-in call would. Ask stack.is_empty / queue.is_empty / heap.is_empty first.

    Heap (priority queue)

    heap.take always returns the smallest value first, however the values arrived. The heap is a binary tree flattened into one array: the children of the node at index i sit at 2*i + 1 and 2*i + 2, and every parent is <= its children. Adding and taking are O(log n). The elements are compared with <, so they are numbers or strings.

    Deque (both ends)

    A queue that is open at both ends: values join and leave at the front and at the back. Two stacks, back to back: front holds the front half reversed (its last element is the deque's first), back holds the rest in order. Each end is O(1); when one side runs dry it is refilled from the other, which keeps every operation O(1) on average.

    Part of the Thunder SDK reference.

    This document describes everything that is built into Thunder, module by module:

    1. How the library is organised – the default module and the built-in modules (section 1).
    2. Modules and files – splitting a program into several files with import (section 2).
    3. The default module – printing, input, conversions, tuples, lists, maps, and functions as values with map, filter, reduce and name_of (section 3).
    4. The always-available modules – math, string, random and bytes.
    5. The modules that must be imported – os (commands, the clock, the environment) and file (reading and writing files). The graphics module (drawing, animation, keyboard and mouse) has its own document: the graphics reference.
    6. What changed in 0.7 – the old names and the new ones.

    The core language, including how to declare modules of your own (module), is described in the language reference. The bytecode reference explains how all of this runs on the virtual machine. When the built-ins are not enough, the native interface reference shows how to call your own C++ code, and the packaging reference how to turn a finished program into a standalone application. The libraries written in Thunder itself (sockets, testing, data structures, algorithms) have their own documents, listed in the SDK reference. In the IDE, this document is under Help > Library reference.

    Samples 25_modules to 27_os (in samples/en/, and in Pashto in samples/ps/) show every feature.

    1. How the library is organised#

    The language's own functions are organised in modules, the same kind of named bundle a program can declare for itself (language reference):

    Module Pashto Available Contains Section
    (the default module)always, no prefixprinting, input, conversions, tuples, lists, maps, higher-order functions, name_of3
    mathریاضيalwaysmath.sqrt, math.sin, math.round, math.max, math.pi, ...4
    stringمتنalwaysstring.trim, string.split, string.format, string.is_int, ...5
    randomتصادفيalwaysrandom.int, random.float, random.seed6
    bytesبایټونهalwaysbytes.from_string, bytes.to_int, ...7
    osسیسټمafter import osos.run, os.args, os.time, os.exit, os.Platform, ...8
    fileفایلafter import filefile.read, file.write, file.exists, file.read_bytes, ...9
    graphicsګرافیکafter import graphicsgraphics.canvas, graphics.circle, graphics.frame, graphics.Color, ...graphics reference
    • The default module needs no prefix. println, len, str, push, map and the other functions of section 3 are written by their own name, everywhere.
    • Every other built-in is written with its module in front: math.sqrt(2.0), string.trim(line), random.int(1, 6). math, string, random and bytes are always there. os, file and graphics reach outside the program (the operating system, the disk, the screen), so a program says that it uses them: import os, import file, import graphics, at the top, without quotes. Using one of their members without the import is error S049.
    • The built-in enums belong to their modules too: graphics.Color.red and os.Platform.linux.
    • A name used without its module is error S067, and the message says where the name lives: 
      main.th:3:9: semantic error [S067]: 'sqrt' belongs to the module 'math': write math.sqrt

      A member that a module does not have is S070 ("the module 'math' has no member called 'foo'").

    • Module names are reserved. No variable, parameter, function or type may be called math, os, random, ... (S065: "'math' is the name of a module; give this variable another name"), and a module of your own cannot be called like a built-in one (S064).
    • The default module's names are reserved too: a function of your own called len or push is S004 (a struct, S028). The names inside the other modules are not: a program may declare its own sqrt or trim, because the built-in ones are math.sqrt and string.trim.
    • Error messages, the debugger, call stacks and the Bytecode tab show the qualified names: runtime error [R027]: 'math.sqrt' is not defined for -1.0.
    import file

var words = string.split("pear apple fig", " ")    # string: always there
println(len(words), " ", sort(words))               # default module: no prefix
println(math.sqrt(2.0), " ", random.int(1, 6))     # math and random: always there
file.write("notes.txt", "Hello")                    # file: needs import file

    Conventions#

    • Positions count characters, not bytes, and start at 0, exactly as len(s) and s[i] do. "پښتو" has 4 characters.
    • Ranges include the start and exclude the end. string.substring("thunder", 1, 4) is "hun", and range(1, 4) is [1, 2, 3]. A range outside the text or array is runtime error R012; Thunder never quietly clips it.
    • New value, or change in place? Functions whose names are verbs that change things (push, pop, insert, remove_at, and remove for maps) change the array or map they are given. Every other function returns a new value and leaves its arguments alone. For example, sort(a) returns a sorted copy.
    • Types are checked when the program is compiled. string.trim(5) and push(names, 3) are compile errors (S010), never runtime surprises. The generic functions (contains, map, zip, ...) work out their result type from their arguments.
    • Every built-in has a Pashto name (tables in section 12).
    • Signatures below are the ones thunderc --language-info reports. They use T, U, A, B, K and V for "any type", as in push(a: T[], value: T).

    2. Modules and files#

    Importing a file#

    # lib/geometry.th
module geometry
    struct Rectangle
        width: int
        height: int

    func area(r: Rectangle): int
        return r.width * r.height
    # main.th
import "lib/geometry"

var room = geometry.Rectangle(4, 3)
println(geometry.area(room))          # 12

    import "name" reads the file name.th (writing .th is optional) and makes everything it declares usable: the modules it declares, whose members are written with the module's name in front (geometry.area), and any declarations outside a module, which are used by their own name, as if they were written in the importing file. Those top-level names must therefore not clash with the program's own names; a clash is reported as for two declarations in one file (S002, S003, S028). Putting a library's declarations in a module avoids clashes, and the language reference describes modules in full (private _names, S064-S070).

    Where files are looked for#

    1. Next to the file that contains the import. main.th finds lib/geometry.th in its own directory. If lib/geometry.th says import "numbers", it means lib/numbers.th.
    2. In the module directories given to the compiler: thunderc -I <dir> (or --module-path <dir>; may be repeated). The IDE passes the directory the program was opened from, so samples and saved files find their files even though the IDE compiles a copy of the editor text.

    If the file is not found, error S045 lists every place that was searched:

    main.th:1:8: semantic error [S045]: module 'lib/shapes' not found (looked for lib/shapes.th, /home/me/thunder/lib/shapes.th)

    What an imported file may contain#

    An imported file only declares things: modules, functions, structs, enums, variables, constants and further imports. Statements such as println(...) or if ... are rejected (S047), so importing a file never prints anything or has other side effects. An imported file may not define main (S048); only the program that is run can.

    Its variables (and the variables of its modules) are ordinary global variables. They are initialised before the importing file's own statements run, wherever the import is written. import itself may only appear at the top level of a file (P016); by convention it is written at the top.

    Each file is loaded once#

    However often a file is imported, directly or through other files, it is loaded once and its variables are initialised once. Two files may therefore both import a third (a "diamond"), and two files may even import each other.

    Language#

    An imported file is compiled in the same language as the program that imports it. A file without a language directive takes the importer's language. A file that declares a different language (# lang: ps in an English program) is rejected with S046; translate it with thunderc --translate. File names are written as they are on disk, in any script.

    Errors in imported files#

    Errors are reported in the imported file, with its own line numbers and source line:

    lib/geometry.th:8:16: semantic error [S027]: function 'geometry.area' must return a value of type 'int' but this value has type 'bool'
    8 |         return true
      |                ^~~~

    Runtime errors name the file too: in geometry.area [lib/geometry.th] (line 8). In the IDE, problems in an imported file are listed in the Problems tab with its file name, the Bytecode tab shows which file each instruction came from, and the debugger names the file while it steps through it.

    Built-in modules#

    import followed by a name without quotes imports a module built into the toolchain: os (in Pashto سیسټم), file (فایل) and graphics (ګرافیک). An unknown name is error S050, which also reminds you that files are imported with quotes. math, string, random and bytes need no import.

    Under the bonnet#

    Each source file gets a number (0 for the program, then 1, 2, ... for the imported files in the order they were loaded). Every token, syntax-tree node, diagnostic and bytecode line-table entry records its file number, and the .thc file lists the file names (bytecode format version 4). Resolving an import is name resolution, so the files are read, tokenised and parsed at the start of semantic analysis. The program is only analysed further if they all load without errors. The semantic analyser then sees one combined program: each file's declarations, then the program's own. It renames every module member to its qualified name (geometry.area) before checking anything, so modules cost nothing at run time.

    3. The default module#

    These functions are written without a prefix. Their names are reserved for them: a function of your own may not be called len or push (S004), nor may a struct or enum (S028).

    Printing, input and output#

    Function Description
    print(value, ...)Writes the values with no separator and no newline.
    println(value, ...)Like print, followed by a newline.
    input(prompt: string = ""): stringWrites prompt first, if there is one (without a newline), then reads one line and returns it without its line break (\n or \r\n). Returns "" at the end of the input.
    end_of_input(): booltrue if there is nothing more to read.

    Formatted printing is println(string.format(...)) (section 5).

    var name = input("What is your name? ")
println(string.format("Hello, {}! Your name has {} letter(s), or {x} in hex.", name, len(name), len(name)))

var total = 0
while not end_of_input()
    var line = string.trim(input())
    if string.is_int(line)
        total = total + to_int(line)
println("total: ", total)

    Where the input comes from:

    • Command line: standard input. Type the lines (end with Ctrl+D on Linux and macOS, or Ctrl+Z then Enter on Windows), or redirect a file: thundervm sum.thc < numbers.txt.
    • IDE: the Input line under the Output panel. It is enabled while a program runs (Run or Debug). Type a line and press Enter or Send; the line is echoed in the output, as a terminal would show it. End input ends the input, so end_of_input() becomes true. A prompt appears as soon as the program writes it, before the program waits.
    • Golden tests: if tests/golden/<language>/<sample>.input exists, the sample reads that file (see 26_input).

    input() and end_of_input() wait until the user has typed a line (or ended the input). A program waiting for input uses no instructions, so the IDE's step limit does not stop it; Stop does.

    Tuples and pairs#

    A pair is a tuple with two elements, (1, "one") of type (int, string) (see the language reference, section 8).

    Function Result Example
    first(t: (A, B, ...)): AThe first element of a tuple (of any size).first((1, "one")) → 1
    second(t: (A, B, ...)): BThe second element of a tuple.second((1, "one")) → "one"
    swap(p: (A, B)): (B, A)The pair with its elements exchanged.swap((1, "one")) → ("one", 1)
    zip(a: A[], b: B[]): (A, B)[]Pairs of the elements at the same positions, as many as the shorter array has.zip([1, 2, 3], ["a", "b"]) → [(1, "a"), (2, "b")]
    enumerate(a: T[]): (int, T)[]Every element paired with its position.enumerate(["x", "y"]) → [(0, "x"), (1, "y")]
    items(m: {K: V}): (K, V)[]The entries of a map as (key, value) pairs, in insertion order.items({"a": 1}) → [("a", 1)]

    first(p) and second(p) mean the same as p.0 and p.1. Pairs are easy to unpack:

    var people = zip(["Ada", "Alan"], [1815, 1912])
for var i = 0, i < len(people), i = i + 1
    var (name, year) = people[i]
    println(name, " was born in ", year)

    Lists (arrays)#

    Changing an array in place:

    Function Effect Example (with a = [3, 1, 2])
    push(a: T[], value: T)Adds value to the end.push(a, 4) → a is [3, 1, 2, 4]
    pop(a: T[]): TRemoves the last element and returns it. Runtime error R013 if a is empty.pop(a) → 2, a is [3, 1]
    insert(a: T[], index: int, value: T)Inserts value at position index (0 to len(a)); later elements move up.insert(a, 0, 9) → a is [9, 3, 1, 2]
    remove_at(a: T[], index: int): TRemoves the element at position index and returns it; later elements move down.remove_at(a, 1) → 1, a is [3, 2]

    An index outside the array is runtime error R003, as for a[i]. Arrays are reference types, so every variable that refers to the array sees the change.

    New arrays:

    Function Result Example
    slice(x: string | T[], start: int, end: int): string | T[]The elements (or characters) from start up to (not including) end.slice([1, 2, 3, 4], 1, 3) → [2, 3], slice("abc", 0, 2) → "ab"
    concat(a: T[], b: T[]): T[]The elements of a followed by those of b.concat([1], [2, 3]) → [1, 2, 3]
    reverse(x: string | T[]): string | T[]The elements (or characters) in reverse order.reverse([1, 2, 3]) → [3, 2, 1], reverse("stressed") → "desserts"
    sort(a: T[]): T[]The elements in ascending order: numbers by value, strings by character code. Equal elements keep their order.sort(["pear", "apple"]) → ["apple", "pear"]
    range(start: int, end: int): int[]The numbers from start up to (not including) end; empty if end <= start.range(1, 5) → [1, 2, 3, 4]

    Searching and summing:

    Function Result Example
    contains(x: string | T[], item): booltrue if an element equals item, or if the text contains the part.contains([1, 2], 2) → true, contains("thunder", "und") → true
    index_of(x: string | T[], item): intThe position of the first element equal to item (or of the first occurrence of the part), or -1.index_of(["a", "b"], "b") → 1, index_of("thunder", "der") → 4
    sum(a: int[]): intThe sum of an int[] or a float[] (0 if empty; overflow is runtime error R002/R025).sum([1, 2, 3]) → 6

    slice, reverse, contains and index_of work on texts and arrays alike, so they are in the default module rather than in string. contains and index_of compare with ==, so they accept the element types == accepts: int, bool, string and tuples. Arrays of structs, arrays and maps would only compare identities, which is rarely what is meant, so they are a compile error (S026). sort accepts int[], float[] and string[].

    Functions as values: map, filter, reduce and name_of#

    A function's name, without parentheses, is a value: a reference to the function. Its type is written with func:

    Type Meaning
    func(int): boola function that takes an int and returns a bool
    func(string, int): stringtwo parameters
    func()no parameters and no result
    (func(int): int)[]an array of functions (the parentheses keep [] off the result type)
     
    func double(n: int): int
    return n * 2

func apply(f: func(int): int, x: int): int
    return f(x)                   # call a function value like a function

var f = double                    # f has type func(int): int
println(f(4), " ", apply(double, 5))    # 8 10
var steps: (func(int): int)[] = [double, f]
println(steps[1](3))              # 6: any expression that gives a function can be called
println(f)                        # <func double>
    • Function values can be stored in variables, arrays, maps, tuples and struct fields, passed as arguments and returned from functions. A module's function is a value too: geometry.area.
    • A variable or field of function type that has not been given a function holds "no function", shown as <func ?>. Calling it is runtime error R020.
    • A local variable that holds a function hides a function with the same name.
    • A function name cannot be assigned to (double = triple is S012); function values cannot be compared with == (S006).
    • Only functions you declare can be values. Built-in functions cannot (map(words, str) is S025), because many of them accept several types. Write a small function instead: func text(n: int): string / return str(n).
    • Thunder has no nested functions, so a function value never captures local variables. There are no closures.

    Higher-order functions:

    Function Result Example
    map(a: T[], f: func(T): U): U[]A new array with f(x) for every element x.map([1, 2, 3], double) → [2, 4, 6]
    filter(a: T[], keep: func(T): bool): T[]A new array with the elements for which keep returns true.filter(range(1, 7), is_even) → [2, 4, 6]
    reduce(a: T[], initial: A, f: func(A, T): A): ACombines the elements from left to right: f(f(initial, a[0]), a[1]) .... Returns initial for an empty array.reduce([1, 2, 3], 0, add) → 6
    name_of(f: func): stringThe name the function was declared with, its module in front.name_of(geometry.area) → "geometry.area"
     
    func double(n: int): int
    return n * 2

func is_even(n: int): bool
    return n % 2 == 0

func add(total: int, n: int): int
    return total + n

func longer(best: string, word: string): string
    if len(word) > len(best)
        return word
    return best

var numbers = range(1, 11)
println(map(numbers, double))                     # [2, 4, 6, ..., 20]
println(filter(numbers, is_even))                 # [2, 4, 6, 8, 10]
println(reduce(numbers, 0, add))                  # 55
println(reduce(["a", "abc", "ab"], "", longer))   # abc

    If the function has the wrong type, the message says which type was needed (? stands for "any result type"):

    semantic error [S051]: argument 2 of 'map' must be a function of type 'func(int): ?' but has type 'func(string): int'

    map and filter work on the elements the array had when they started, so the function may safely change the array. A runtime error inside the function is reported in the function, with the call from map in the call stack. In the IDE's debugger you can step into the function each time map calls it.

    name_of answers with the name a function value refers to, whatever variable holds it. The testing library uses it to put a test into the suite of its module (testing reference):

    module shapes
    func square(n: int): int
        return n * n

func cube(n: int): int
    return n * n * n

var f = shapes.square
println(name_of(f), " ", name_of(cube))     # shapes.square cube
println(f)                                   # <func shapes.square>

    4. The math module#

    Always available, no import. These are the companions of the float type (language reference, section 3). Every one of them also accepts whole numbers, which are widened, so math.sqrt(2) and math.round(2) are fine.

    Function Result Example
    math.abs(x: int | float): int | floatThe distance from zero; int in, int out.math.abs(-3.25) → 3.25
    math.min(a, b), math.max(a, b)The smaller / larger of two numbers, or the earlier / later of two texts.math.max(1.5, 0.5) → 1.5
    math.round(x: float): intThe nearest whole number; a half is rounded away from zero.math.round(2.5) → 3
    math.floor(x: float): int, math.ceil(x: float): intThe whole number below / above.math.floor(2.5) → 2, math.ceil(2.1) → 3
    math.sqrt(x: float): floatSquare root; runtime error R027 if x is negative.math.sqrt(9.0) → 3.0
    math.pow(x: float, y: float): floatx to the power y.math.pow(2.0, 10.0) → 1024.0
    math.exp(x: float): float, math.log(x: float): floatex, and the natural logarithm (R027 if x <= 0).math.log(1.0) → 0.0
    math.sin(x: float): float, math.cos(x: float): float, math.tan(x: float): floatTrigonometry, with the angle in radians.math.sin(math.pi() / 2.0) → 1.0
    math.pi(): float3.141592653589793.

    A result that is too large for a float is runtime error R025, and dividing by 0.0 is R001: Thunder never produces infinity or "not a number".

    5. The string module#

    Always available, no import. Strings themselves stay immutable: these functions return new strings. (len, slice, reverse, contains and index_of, which work on texts and arrays alike, are in the default module.)

    string.to_upper(s: string): strings with a–z changed to A–Z.string.to_upper("Thunder 2") → "THUNDER 2"
    string.to_lower(s: string): strings with A–Z changed to a–z.string.to_lower("ABC") → "abc"
    string.split(s: string, separator: string): string[]The pieces between the separators. With "", the single characters.string.split("a,b,,c", ",") → ["a", "b", "", "c"]
    string.join(parts: string[], separator: string): stringThe strings in parts with separator between them.string.join(["a", "b"], ", ") → "a, b"
    string.replace(s: string, old: string, new: string): strings with every old replaced by new (from left to right, without overlaps).string.replace("a.b.c", ".", "-") → "a-b-c"
    string.starts_with(s: string, prefix: string): booltrue if s begins with prefix.string.starts_with("thunder", "thu") → true
    string.ends_with(s: string, suffix: string): booltrue if s ends with suffix.string.ends_with("thunder", "er") → true
    string.repeat(s: string, n: int): strings written n times.string.repeat("ab", 3) → "ababab"

    string.is_number(s: string): booltrue if to_float(s) would succeed.string.is_number("x") → false
    string.format(template: string, values...): stringThe template with each {} replaced by the next value; {x} writes a whole number in hexadecimal, {b} in binary; {{ and }} are literal braces.string.format("{} is {x}", 10, 10) → "10 is 0xa"

    Notes:

    • Only the English letters a–z and A–Z change case. Pashto and other Arabic-script languages have no upper and lower case.
    • string.trim removes ASCII white space (space, tab, line breaks, vertical tab, form feed).
    • string.split(s, sep) always returns at least one piece: string.split("", ",") is [""]. string.join(string.split(s, sep), sep) gives back s.
    • string.replace(s, "", new) returns s unchanged (there is nothing to look for).
    • string.is_int and to_int accept surrounding spaces and the digits of every supported script ("۴۲").
    • Formatted printing is println(string.format(...)). Too few or too many values for the template is R031; {x}/{b} on a value that is not a whole number is R032.

    Runtime errors: a range outside the text (R012), string.repeat with a negative count (R014) or a result longer than the VM's size limit (R007), string.char_code of a string that is not exactly one character long (R015), and string.from_char_code of a number that is not a code point (R016).

    6. The random module#

    Always available, no import.

    Function Result
    random.int(low: int, high: int): intA random whole number from low to high, both included (low > high is runtime error R023).
    random.float(): floatA random decimal from 0 (included) to 1 (excluded).
    random.seed(seed: int)Restarts the sequence: after the same seed, the same numbers follow.

    Without a seed, every run is different. thundervm --seed n (and the golden tests) start from a fixed seed. Thunder uses its own generator (SplitMix64), so a seed gives the same numbers on every operating system and compiler. Simulations and games use these a lot; see the graphics reference.

    7. The bytes module#

    Bytes#

    A byte is a whole number from 0 to 255, and a byte[] is raw data: the contents of a file as it is on disk, a sound, an image, a network packet. A byte widens to an int wherever an int is wanted, so the arithmetic and bit operators work on it; a whole-number literal from 0 to 255 written where a byte is wanted is that byte, and to_byte (default module) narrows everything else (see the language reference, section 3).

    The bytes module is always available, no import. It converts between bytes and texts or whole numbers:

    Function Result Example
    to_byte(n: int): byte (default module)The low 8 bits of a whole number.to_byte(255) → 255, to_byte(256) → 0, to_byte(-1) → 255
    bytes.from_string(s: string): byte[]The bytes of the text in UTF-8 (one byte per English letter, two or more per Pashto letter).bytes.from_string("Az") → [65, 122], bytes.from_string("ژ") → [218, 152]
    bytes.to_string(data: byte[]): stringThe text the bytes spell in UTF-8; what is not valid UTF-8 becomes U+FFFD.bytes.to_string([72, 105]) → "Hi"
    bytes.to_int(data: byte[], start: int, count: int, little_endian: bool, signed: bool): intThe whole number stored in count bytes (1 to 8) from position start, lowest byte first when little_endian is true, read as two's complement when signed is true.bytes.to_int([52, 18], 0, 2, true, false) → 4660 (0x1234)
    bytes.from_int(value: int, count: int, little_endian: bool): byte[]The low count bytes (1 to 8) of a whole number, lowest first when little_endian is true.bytes.from_int(0x1234, 2, false) → [18, 52], bytes.from_int(-2, 2, true) → [254, 255]

    Everything that works on arrays works on a byte[]: len, indexing, push, slice, concat, reverse, contains, sort, sum (an int), for ... in, array(n, to_byte(0)) for a buffer of zeros. hex(b), bin(b) and string.format("{x}", b) show a byte's bits; str(b) and println(b) show its value. The file module reads and writes files as bytes (file.read_bytes, file.write_bytes, file.append_bytes, section 9) and the sockets library sends and receives them (socket.send_bytes, socket.receive_bytes, udp.send_bytes, udp.receive_bytes: the sockets reference). A byte[] may also cross the native interface.

    Little-endian is the order of WAV and BMP files and of most processors (44100 is stored as [68, 172, 0, 0]); big-endian is the order of the network and of PNG. Audio samples in a WAV file are 16-bit signed little-endian numbers: bytes.to_int(data, 44 + 2 * i, 2, true, true) reads sample i, and bytes.from_int(sample, 2, true) writes one.

    Runtime errors: a count outside 1..8 is R022; a range outside the data is R012.

    Paths are written with / (Windows also accepts \). A file that cannot be read is runtime error R017; one that cannot be written or removed is R018. The message gives the reason.

    10. What changed in 0.7#

    13. Under the bonnet#

    • Built-in modules cost nothing. A qualified name such as math.sqrt is resolved by the semantic analyser; the bytecode calls the built-in by its number (CALL_BUILTIN), exactly as before. The Bytecode tab and thunderc --emit asm show the qualified name next to the number.
    • Two instructions for function values. FUNC_REF f pushes a function value. CALL_VALUE n pops a function value and calls it with the n arguments below it, so steps[1](3) compiles to "push 3, push steps[1], CALL_VALUE 1". The unset function value is FUNC_REF 65535.
    • Built-ins that call Thunder functions. map, filter and reduce call the function from inside the VM: the VM pushes the arguments, enters the function and runs instructions until it returns, then continues the built-in. The debugger, the step limit and the call-depth limit all apply to these calls.
    • Input. The VM reads from an input stream (standard input for thundervm); the IDE connects a pipe to it and shows the output as it arrives rather than line by line, so a prompt is visible while the program waits.
    • Exit status. os.exit(code) stops the VM normally, not as an error. The status is in the exit_code field of thundervm --result-json and of the debugger's trace.
    • Bytecode format version 4 adds the list of source files to the header and a file number to each line-table entry (bytecode reference, section 4).
    • Where the code is. Built-in names, modules and signatures: src/core/builtins.cpp; type checking: check_builtin in src/core/sema.cpp; execution: src/core/vm_builtins.cpp; operating-system services: src/core/os.cpp; file loading: ModuleLoader in src/core/compiler.cpp.

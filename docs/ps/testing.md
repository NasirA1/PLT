# د ازموینې لارښود

تندر ازموینې په خپلو بېلو **د ازموینې فایلونو** کې ساتي. هره ازموینه په **`@ازموینه`** نښه
کړئ - یوه دنده، یا ټول یو جوړښت یا ټولګی، چې بیا د ازموینو یوه **ډله** (suite) ده - د
`تمه.برابر()` او ملګرو سره یې ووایئ چې څه باید رښتیا وي، او فایل وچلوئ: ژباړونکی ازموینې
پیدا کوي، د ازموینو چوکاټ راوړي، ازموینې یوه په بل پسې چلوي او بیا لنډیز چاپوي. هغه جوړښت
چې په **`@پېښه ګر`** نښه شوی وي د یوه برسېر ځای نیسي او ثبتوي چې څنګه وکارول شو. چوکاټ دوه
ټولګي دي: **`ازموینه`** ازموینې چلوي او **`تمه`** وايي چې څه باید رښتیا وي. په هغه کې هېڅ
بهرنی نشته - دا ساده تندر دی، په [`lib/thunder/ps/testing.th`](../../lib/thunder/ps/testing.th)
کې، د لوستلو لپاره لیکل شوی. انګلیسي فایل ([`lib/thunder/en/testing.th`](../../lib/thunder/en/testing.th))
همدا چوکاټ له انګلیسي نومونو سره دی؛ دواړه پخپله، د اوزارو تر څنګ، موندل کېږي.

**ویې آزمویئ:** [`samples/ps/27_testing.th`](../../samples/ps/27_testing.th) د
[`samples/ps/lib/scores.th`](../../samples/ps/lib/scores.th) کوډ له یوازې ازموینو، د ټولګي
یوې ډلې، د جوړښت یوې ډلې او دوو پېښه ګرانو سره ازمویي (انګلیسي:
[`samples/en/27_testing.th`](../../samples/en/27_testing.th))؛ د IDE د بېلګو په لړ کې د
*۲۸ - ازموینه* په نوم ده.

## د ازموینو فایل

هغه کوډ چې ازمویل کېږي په یوه کتابتون فایل کې اوسي، چې پروګرام او د ازموینې فایل دواړه یې
راوړلای شي:

```thunder
# ژبه: ps
# lib/shop.th - هغه کوډ چې ازمویل کېږي
ټولګی هټۍ
    دنده تر_ټولو_لوی(ارزښتونه: عدد[]): عدد
        متغیر غوره = ارزښتونه[۰]
        تکرار ارزښت په ارزښتونه
            که ارزښت > غوره
                غوره = ارزښت
        راګرځه غوره

    دنده پالیندروم_دی(کلمه: متن): منطقي
        راګرځه متن.سرچپه کړه(کلمه) == کلمه

    # بیې له کومه راځي: په پروګرام کې د بیو لړ، په ازموینه کې یو ځای نیوونکی.
    برسېر بیه_ورکوونکی
        دنده بیه_یې(شی: متن): عدد

    جوړښت ټوکری
        شیان: متن[]

        دنده ورزیات_کړه(شی: متن)
            ورزیات کړه(شیان، شی)

        دنده ټول_یې(بیې: بیه_ورکوونکی): عدد
            متغیر ټول = ۰
            تکرار شی په شیان
                ټول += بیې.بیه_یې(شی)
            راګرځه ټول
```

د ازموینې فایل دا راوړي او ازموینې اعلانوي - بل هېڅ نه:

```thunder
# ژبه: ps
راوړه "lib/shop"                        # هغه کوډ چې ازمویل کېږي

@ازموینه                                # یوه ازموینه، د «د لړۍ تر ټولو لوی» په نوم
دنده د_لړۍ_تر_ټولو_لوی()
    تمه.برابر(هټۍ.تر_ټولو_لوی([۳، ۹، ۲])، ۹)
    تمه.برابر(هټۍ.تر_ټولو_لوی([-۵])، -۵)

@ازموینه("اعشاري په زغم پرتله کېږي")
دنده اعشاري_شمېرې()
    تمه.نږدې(۱٫۰ / ۳٫۰، ۰٫۳۳۳۳، ۰٫۰۰۱)

@ازموینه                                # ټولګی یوه ډله ده: عامې دندې یې ازموینې دي
ټولګی کلمې
    دنده پالیندرومونه()
        تمه.رښتیا_وي(هټۍ.پالیندروم_دی("کاک"))
        تمه.درواغ_وي(هټۍ.پالیندروم_دی("تندر"))

    دنده لړۍ_د_توکو_له_مخې_پرتله_کېږي()
        تمه.برابر(متن.وېشه("الف،ب"، "،")، ["الف"، "ب"])

@ازموینه("یو ټوکری")                     # جوړښت یوه ډله ده: هره ازموینه نوی د_ټوکري_ازموینې اخلي
جوړښت د_ټوکري_ازموینې
    _ټوکری: هټۍ.ټوکری

    د_ټوکري_ازموینې()                   # چمتووالی: له هرې ازموینې مخکې چلېږي
        _ټوکری = هټۍ.ټوکری()
        _ټوکری.ورزیات_کړه("چای")

    دنده له_یوه_شي_پیلېږي()
        تمه.برابر(اوږدوالی(_ټوکری.شیان)، ۱)

    دنده یو_شی_ورزیاتوي()
        _ټوکری.ورزیات_کړه("شیدې")
        تمه.برابر(_ټوکری.شیان، ["چای"، "شیدې"])

    دنده وتړه()                          # پاکول: له هرې ازموینې وروسته چلېږي
        _ټوکری.شیان = []

@پېښه ګر                                 # د هټۍ.بیه_ورکوونکی برسېر ځای نیوونکی
جوړښت ثابتې_بیې: هټۍ.بیه_ورکوونکی
    دنده بیه_یې(شی: متن): عدد
        راګرځه ۳

@ازموینه("ټوکری خپلې بیې جمع کوي")
دنده ټولې_بیې()
    متغیر ټوکری = هټۍ.ټوکری(["چای"، "شیدې"])
    متغیر بیې = ثابتې_بیې()
    تمه.برابر(ټوکری.ټول_یې(بیې)، ۶)
    بیې.تمه_د_بللو("بیه_یې"، ۲)
    تمه.برابر(بیې.بلنې()، ["بیه_یې(چای)"، "بیه_یې(شیدې)"])
```

نه `راوړه "testing"` شته او نه داسې بلنه چې ازموینې وچلوي: ژباړونکی دواړه ورزیاتوي. چلول یې
(`thunderc shop_test.th && thundervm shop_test.thc`) هرې ازموینې ته یوه کرښه چاپوي - د ډلې
نوم د خپلو ازموینو پورته، چې ننوتې چاپېږي - او یو لنډیز: لومړی د هرې ډلې شمېرې، بیا ټولټال:

```
✓ د لړۍ تر ټولو لوی
✓ اعشاري په زغم پرتله کېږي
کلمې
  ✓ پالیندرومونه
  ✓ لړۍ د توکو له مخې پرتله کېږي
یو ټوکری
  ✓ له یوه شي پیلېږي
  ✓ یو شی ورزیاتوي
✓ ټوکری خپلې بیې جمع کوي
کلمې: ۲ تېرې شوې، ۰ ناکامې
یو ټوکری: ۲ تېرې شوې، ۰ ناکامې
۷ تېرې شوې، ۰ ناکامې
```

هغه ازموینه چې تمه یې پوره نه شي پر ځای یې چاپوي چې څه ناسم شول، او لنډیز پروګرام د **وتلو
کوډ ۱** سره پای ته رسوي، نو یو سکریپټ - یا یو سمونګر - پوهېدلی شي. که په `تر_ټولو_لوی` کې
تېروتنه وي (د `>` پر ځای `<`):

```
✗ د لړۍ تر ټولو لوی: تمه ۹ وه، ۲ ترلاسه شو
✓ اعشاري په زغم پرتله کېږي
کلمې
  ✓ پالیندرومونه
  ✓ لړۍ د توکو له مخې پرتله کېږي
یو ټوکری
  ✓ له یوه شي پیلېږي
  ✓ یو شی ورزیاتوي
✓ ټوکری خپلې بیې جمع کوي
کلمې: ۲ تېرې شوې، ۰ ناکامې
یو ټوکری: ۲ تېرې شوې، ۰ ناکامې
۶ تېرې شوې، ۱ ناکامې
```

ازموینې په هغه ترتیب چلېږي چې اعلان شوې دي. هره ناکامه تمه خپله `✗` کرښه چاپوي، نو هغه
ازموینه چې درې ناسمې تمې لري درې واړه راپوروي؛ ازموینه یو ځل ناکامه شمېرل کېږي.

## ازموینې نښه کول: `@ازموینه`

**نښه** (annotation) `@` او یو نوم دی، که وغواړئ په قوسونو کې له یوه متن سره، د یوه اعلان
له کرښې (یا کرښو) مخکې: `@ازموینه`، `@ازموینه("جمع سمه ده")`. په همغه کرښه یې تبصره راتلای
شي. د ژبې لارښود په عمومي ډول نښې بیانوي (۹ برخه، «د ازموینې فایلونه او نښې»). `@ازموینه`
څلور شیان نښه کولای شي:

| `@ازموینه` پر | جوړوي | نوم |
| --- | --- | --- |
| هغه دنده چې پارامټر او پایله نه لري | یوه ازموینه | د تشریح له مخې، یا د دندې نوم چې هر `_` یې په تشه بدل شي: `د_لړۍ_تر_ټولو_لوی` «د لړۍ تر ټولو لوی» دی |
| یو جوړښت | یوه **ډله**: هره عامه دنده (چې په `_` نه پیلېږي) چې پارامټر او پایله نه لري، پرته له `وتړه`، یوه ازموینه ده | ډله د تشریح یا د جوړښت د نوم له مخې؛ هره ازموینه د خپلې دندې د نوم له مخې، لکه پورته |
| یو ټولګی | یوه **ډله**: هره عامه دنده چې پارامټر او پایله نه لري یوه ازموینه ده | ډله د تشریح یا د ټولګي د نوم له مخې |
| د داسې جوړښت یوه دنده، یا د داسې ټولګي یوه دنده، چې پخپله نښه شوی نه وي | یوازې هماغه: د هغې ډلې یوه ازموینه | د خپلې تشریح یا نوم له مخې |

تشریح هغه نوم دی چې لیکنه یې ښيي، نو بشپړه جمله کېدای شي. د نښه شوي جوړښت یا ټولګي دننه،
یو غړی لا هم خپل `@ازموینه("...")` لرلای شي، چې تشریح ورکړي (په بېلګه کې
`@ازموینه("دوه ځله ورزیاتوي") دنده دوه_چنده_کوي()`). هغه دندې چې پارامټر اخلي، پایله
راګرځوي یا په `_` پیلېږي مرستندویې دي: په ډله کې په ساده ډول ازموینې نه دي. که په څرګنده نښه
شي، هغه دنده چې د ازموینې په توګه نشي چلېدای تېروتنه ده (`S087`)، همداسې عمومي دنده (`S088`)
او په یوه ډله کې د یوه نوم دوه ازموینې (`S089`).

هغه د ازموینې دنده چې په هېڅ ټولګي یا نښه شوي جوړښت کې نه وي د هېڅ ډلې نه ده: `✓ نوم` چاپوي،
پرته له سرلیک او پرته له ننوتلو.

### له جوړښتونو جوړې ډلې: چمتووالی او پاکول

د جوړښت د ډلې هره ازموینه د جوړښت پر یوې **نوې بېلګې** چلېږي، چې جوړوونکی یې جوړوي. نو
جوړوونکی **چمتووالی** (fixture) دی - هغه پیل چې هره ازموینه ترې پیلېږي - او هېڅ ازموینه هغه
څه نه ویني چې بلې کړي وي: په بېلګه کې `یو_شی_ورزیاتوي` خپل ټوکري ته ورزیاتوي، او
`له_یوه_شي_پیلېږي` لا هم یو شی مومي، که هره یوه لومړی وچلېږي. کله چې جوړښت د `وتړه()`
(انګلیسي `close()`) دنده ولري، له هرې ازموینې وروسته چلېږي چې پاکول وکړي - هغه فایل ړنګ کړي
چې ازموینې لیکلی، یوه اړیکه وتړي. `وتړه` پخپله هېڅکله ازموینه نه ده. د هرې ازموینې لپاره
ژباړونکی په حقیقت کې دا لیکي:

```
متغیر ډله = د_ټوکري_ازموینې()
ډله.یو_شی_ورزیاتوي()
ډله.وتړه()
```

ډله پرته له دلیلونو جوړېږي، نو جوړوونکی یې دلیل نشي اخیستلای (`S090`). برخې یې د ازموینې
حالت دی؛ یوه شخصي دنده (`_دوه_ځله_ورزیات_کړه(اندازه: عدد)`) مرستندویه ده چې ازموینې یې
شریکوي.

### له ټولګو جوړې ډلې

هغه ټولګی چې په `@ازموینه` نښه شوی وي د خپلو هغو عامو دندو ډله ده چې پارامټر نه لري. د
جوړښت د ازموینو په خلاف، دوی د ټولګي متغیرونه شریکوي، چې له یوې ازموینې بلې ته خپل ارزښتونه
ساتي، نو د ټولګي ډله هغو ازموینو ته ښه ده چې خپل حالت ته اړتیا نه لري. په ټولګي کې ازموینه
کولای شي د ټولګي شخصي مرستندویې (`_نوم`) وکاروي، لکه هر غړی.

## د ازموینې فایلونه او د پروګرام فایلونه

ازموینې او اصلي کوډ بېل ساتل کېږي، او ژباړونکی یې ګوري:

* **هغه فایل چې کومه `@ازموینه` ولري د ازموینې فایل دی.** یوازې اعلانونه لري - دندې،
  جوړښتونه، ګډونونه، برسېرونه، ګڼنې، ټولګي، متغیرونه، ثابتونه او راوړنې - او **د سر کچې هېڅ
  امر او هېڅ `اصلي()` نه لري** (`S091`): هغه امرونه چې دا چلوي ژباړونکی لیکي.
* **د ازموینو ټولګی پخپله راځي.** د ازموینې په فایل کې ژباړونکی `"testing"` پخپله راوړي
  (که راوړنه پخپله ولیکئ هم منل کېږي، او هېڅ نه بدلوي).
* **اصلي پروګرام د ازموینې کوډ نشي کارولای.** هغه پروګرام چې اصلي فایل یې هېڅ `@ازموینه` نه
  لري نه `راوړه "testing"` لیکلای شي او نه `@پېښه ګر` اعلانولای شي - نه په خپل فایل کې او نه په
  هغه فایل کې چې راوړي یې (`S092`).
* **هغه فایل چې ازموینې لري نشي راوړل کېدای** (`S093`، د `راوړه` پر ځای راپور کېږي): ازموینې
  چلېږي، نه کارېږي. نو هغه کوډ چې ازمویل کېږي په کتابتون فایلونو کې اوسي، چې پروګرام او د
  ازموینې فایل دواړه یې راوړي.
* **شریک پېښه ګران** په داسې یوه مرستندویه فایل کې ځي چې ازموینې نه لري - `lib/fakes.th` له څو
  `@پېښه ګر` جوړښتونو سره - چې څو د ازموینې فایلونه یې راوړلای شي (پروګرام یې نشي راوړلای،
  د پورتنۍ قاعدې له مخې).

`ازموینه` او `تمه` د ټولګو نومونه دي، نو د ازموینې په فایل کې د متغیرونو یا دندو نومونه نشي
کېدای (`S065`).

## پېښه ګران: د برسېرونو ځای نیوونکي

هغه کوډ چې له بهرنۍ نړۍ سره خبرې کوي - ساعت، د بیو لړ، فایل، ساکټ - تر ټولو اسانه هغه وخت
ازمویل کېږي چې دا نړۍ د یوه **برسېر** په بڼه ترلاسه کړي (پورته `بیې: بیه_ورکوونکی`)، نه دا چې
پخپله ورپسې لاړ شي. بیا ازموینه ورته یو **پېښه ګر** ورکوي: هغه جوړښت چې په `@پېښه ګر` نښه شوی
او هغه برسېرونه نوموي چې ځای یې نیسي.

```thunder
# ژبه: ps
@پېښه ګر
جوړښت ثابتې_بیې: هټۍ.بیه_ورکوونکی       # هر شي ته ۳ ځوابوي
    دنده بیه_یې(شی: متن): عدد
        راګرځه ۳

@پېښه ګر
جوړښت بې_بیې: هټۍ.بیه_ورکوونکی          # بې تنې: هره دنده په اصلي ارزښت ځوابوي
```

د `@پېښه ګر` جوړښت لپاره ژباړونکی ګډون **`ازموینه.پېښه_ګر`** رانغاړي او د نومول شوو برسېرونو
هره دنده داسې جوړوي چې **خپله بلنه ثبت کړي** - د دندې نوم او دلیلونه یې د متن په بڼه، لکه
`متن کړه` یې ښيي - او بیا ځواب ورکړي: که جوړښت د همغه نوم خپله دنده ولري له هغې سره، کنه هېڅ
نه کوي او د خپلې پایلې د ډول اصلي ارزښت راګرځوي (`۰`، `""`، `درواغ`، `هېڅ`، `[]`). هغه پېښه ګر
چې هېڅ دنده نه لیکي تنې ته اړتیا نه لري. هغه پېښه ګر چې هېڅ برسېر نه نوموي د هېڅ شي ځای نه
نیسي (`S094`).

ازموینه له پېښه ګران پوښتي چې څه وشول:

| دنده | ځواب |
| --- | --- |
| `وبلل_شو(غړی: متن): منطقي` | `رښتیا` که «غړی» لږ تر لږه یو ځل بلل شوی وي. |
| `د_بلنو_شمېر(غړی: متن): عدد` | «غړی» څو ځله بلل شوی. |
| `دلیلونه_یې(غړی: متن): متن[][]` | «غړي» ته د هرې بلنې دلیلونه، په ترتیب، هر یو د متن په بڼه: `[["چای"]، ["شیدې"]]`. |
| `بلنې(): متن[]` | هره بلنه، په ترتیب، د بلنې په بڼه لیکل شوې: `["ولوله(ک)"، "خوندي_کړه(ک، ۴۲)"]`. |
| `بلنې_هېرې_کړه()` | تر اوسه ثبت شوې بلنې هېروي (چې یوازې هغه څه وکتل شي چې وروسته کېږي). |
| `تمه_د_بللو(غړی: متن، ځله: عدد)` | یوه تمه: اوسنۍ ازموینه ناکامه کوي مګر دا چې «غړی» سم «ځله» بلل شوی وي - `تمه وه چې بیه_یې ۲ ځله وبلل شي، خو ۰ ځله وبلل شو`. |

```thunder
# ژبه: ps
@ازموینه
دنده پېښه_ګر_په_اصلي_ارزښتونو_ځوابوي()
    متغیر ټوکری = هټۍ.ټوکری(["چای"])
    متغیر بیې = بې_بیې()
    تمه.برابر(ټوکری.ټول_یې(بیې)، ۰)                       # بیه_یې ۰ ځواب ورکړ
    تمه.برابر(بیې.دلیلونه_یې("بیه_یې")، [["چای"]])
    بیې.بلنې_هېرې_کړه()
    تمه.درواغ_وي(بیې.وبلل_شو("بیه_یې"))
```

پېښه ګر کولای شي خپلې برخې ولري (`وخت: عدد`، چې `پېښه_ګر_ساعت(وخت: ۹)` یې ټاکي) چې ازموینه
یې ځوابونه وټاکي. `@پېښه ګر` یوازې پر جوړښت راځي (`S085`) او تشریح نه اخلي (`S086`).

## دندې

ټولګی `تمه`:

| دنده | څه کوي |

| `تمه.رښتیا_وي(شرط: منطقي)` | ناکامه، مګر دا چې شرط رښتیا وي. |
| `تمه.درواغ_وي(شرط: منطقي)` | ناکامه، مګر دا چې شرط درواغ وي. |
| `تمه.برابر<ت>(ترلاسه: ت، تمه_شوی: ت)` | ناکامه، مګر دا چې دواړه یو شان چاپ شي - نو لړۍ، ټاپلونه، نقشې او جوړښتونه د خپلو توکو له مخې پرتله کېږي؛ پیغام دواړه ښيي: `تمه [۱، ۴، ۹] وه، [۱، ۴، ۸] ترلاسه شو`. |
| `تمه.نابرابر<ت>(ترلاسه: ت، ناغوښتل: ت)` | ناکامه کله چې دواړه یو شان چاپ شي. |
| `تمه.نږدې(ترلاسه: اعشاري، تمه_شوی: اعشاري، زغم: اعشاري)` | د اعشاري شمېرو لپاره، چې لږ کله بشپړ برابرې وي: ناکامه، مګر دا چې «ترلاسه» له «تمه_شوی» څخه په «زغم» کې وي. |

ټولګی `ازموینه`:

| غړی | څه دی |
| --- | --- |
| `ازموینه.ناکامه_کړه(پیغام: متن)` | اوسنۍ ازموینه د خپل پیغام سره ناکامه کوي. |
| `ازموینه.وچلوه(ډله: متن، نوم: متن، بدنه: دنده())` | دنده «بدنه» د «ډله» د «نوم» ازموینې په توګه چلوي (`""` که ډله نه وي): `✓ نوم` که هره تمه یې پوره شوه، `✗ نوم: پیغام` د هرې هغې لپاره چې پوره نه شوه. ژباړونکی د هرې ازموینې لپاره یوه بلنه لیکي. |
| `ازموینه.پای_ته_ورسوه()` | د هرې ډلې `ډله: N تېرې شوې، M ناکامې` چاپوي (کله چې له یوې زیاتې ډلې وي)، بیا `N تېرې شوې، M ناکامې`، او که کومه ازموینه ناکامه وي پروګرام د وتلو کوډ ۱ سره پای ته رسوي. ژباړونکی بلنه یې له وروستۍ ازموینې وروسته لیکي. |
| `ازموینه.د_ازموینو_چلوونکی` | هغه یوازینی `ازموینه.چلوونکی` چې `وچلوه`، `ناکامه_کړه` او `پای_ته_ورسوه` یې کاروي. |
| `ازموینه.چلوونکی`، `ازموینه.پایله` | پخپله د ازموینو چوکاټ (راتلونکې برخه). |
| `ازموینه.پېښه_ګر` | هغه ګډون چې هر `@پېښه ګر` جوړښت یې رانغاړي (تېره برخه). |

## څنګه کار کوي

چوکاټ یو کوچنی د شیانو (object) جوړښت دی، چې لېوال لوستونکی یې په `lib/thunder/ps/testing.th`
کې تعقیبولای شي:

* **`جوړښت پایله`** - په یوې ازموینې څه وشول: `ډله`، `نوم` او `ناکامۍ` (د ناکامو تمو پیغامونه)،
  او `تېره_شوه()`، چې رښتیا ده کله چې هېڅ ناکامي نه وي.
* **`جوړښت چلوونکی`** - ازموینې چلوي او `پایلې` یې ساتي. `غواړي(ډله، نوم)` وايي چې امر کرښې
  یوه ازموینه ټاکلې که نه؛ `وچلوه(ډله، نوم، بدنه)` یې چلوي، کله چې ډله بدله شي د ډلې سرلیک
  چاپوي، او یوه `پایله` ثبتوي؛ `ناکامه_کړه(پیغام)` روانې ازموینې ته یوه ناکامي ورزیاتوي او د
  هغې `✗` کرښه چاپوي؛ `شمېرې(ډله)` ځوابوي چې د یوې ډلې (`""`: د ټولو) څو ازموینې تېرې او څو
  ناکامې شوې؛ `راپور()` لنډیز چاپوي او د ناکامیو شمېر ځوابوي.
* **`متغیر د_ازموینو_چلوونکی = چلوونکی(سیسټم.دلیلونه())`** - د ټولګي یوازینی چلوونکی، چې د
  پروګرام له دلیلونو جوړ شوی. `ازموینه.وچلوه`، `ازموینه.ناکامه_کړه` او `ازموینه.پای_ته_ورسوه`
  خپل کار ده ته سپاري، او `ازموینه.پای_ته_ورسوه()` پروګرام د وتلو کوډ ۱ سره پای ته رسوي کله
  چې `د_ازموینو_چلوونکی.راپور()` ناکامۍ وشمېرلې.

کله چې د ازموینې فایل جوړوي، ژباړونکی `"testing"` راوړي، د اعلان په ترتیب د هرې ازموینې لپاره
یوه `ازموینه.وچلوه(ډله، نوم، بدنه)` ورزیاتوي - چې «بدنه» د ازموینې دنده ده، یا، د جوړښت د ډلې
لپاره، داسې دنده چې بېلګه جوړوي، دنده یې بولي او `وتړه()` بولي - او بیا
`ازموینه.پای_ته_ورسوه()`. `thunderc --emit ast` دا امرونه ښيي. `thunderc --json` هغه ازموینې
راپوروي چې موندلې یې دي، او سمونګري همداسې یې لړ کوي:

```
"tests": [{"suite": "", "name": "د لړۍ تر ټولو لوی", "function": "د_لړۍ_تر_ټولو_لوی", "line": 4}, ...]
```

`function` د ازموینې د دندې بشپړ نوم دی (`د_ټوکری_ازموینې.یو_شی_ورزیاتوی` - د `ي` او `ی` له یو شان کولو وروسته) او `line` د هغې د
`@ازموینه` کرښه (یا، د هغې ازموینې لپاره چې ډله یې ښيي، د نوم یې کرښه).

## د ځینو ازموینو چلول

د پروګرام دلیلونه ازموینې ټاکي، او نورې نه پیلېږي. بې دلیلونو هره ازموینه چلېږي. دلیل کېدای
شي:

| دلیل | څه چلوي |
| --- | --- |
| د ازموینې نوم: `"د لړۍ تر ټولو لوی"` | د هغه نوم هره ازموینه، په هره ډله کې چې وي |
| د ډلې نوم: `کلمې` | د هغې ډلې هره ازموینه |
| `ډله/ازموینه`: `"یو ټوکری/یو شی ورزیاتوي"` | د هغې یوې ډلې همدا یوه ازموینه |

څو دلیلونه، څو انتخابونه:

```
$ thundervm shop_test.thc کلمې
کلمې
  ✓ پالیندرومونه
  ✓ لړۍ د توکو له مخې پرتله کېږي
۲ تېرې شوې، ۰ ناکامې
$ thundervm shop_test.thc "یو ټوکری/یو شی ورزیاتوي" "د لړۍ تر ټولو لوی"
✓ د لړۍ تر ټولو لوی
یو ټوکری
  ✓ یو شی ورزیاتوي
۲ تېرې شوې، ۰ ناکامې
```

ازموینې بیا هم د اعلان په ترتیب چلېږي، که دلیلونه په هر ترتیب وي. VS Code د خپل د ازموینو لړ
(Test Explorer) له لارې یوه ازموینه یا یوه ډله همداسې چلوي (لاندې)، او یو سکریپټ هغه یوه بیا
چلوي چې ناکامه شوه.

## څه نشي کولای

چوکاټ د تندر څو سوه کرښې دی، او په قصد کوچنی ساتل کېږي.

* **ډلې هو؛ ډله په ډله کې نه.** ډله یو جوړښت یا یو ټولګی دی، او هېڅ یو په ډله کې نه ځي، نو
  په ډلو کې ډلې نشته.
* **د تېروتنو نیول نشته.** په تندر کې استثناوې نشته: د ازموینې دننه د اجرا تېروتنه (له پایه
  اخوا شاخص، پر صفر وېش) ټول پروګرام د معمول راپور سره دروي، لکه هر بل ځای - وروسته ازموینې
  نه چلېږي. نو ازموینه نشي کتلای چې یو څه *ناکامېږي*؛ پر ځای یې هغه شرط وازمویئ چې ناکامي به
  راوړي (`تمه.رښتیا_وي(اوږدوالی(ارزښتونه) > ۰)`).
* **پېښه ګران یوازې د برسېرونو ځای نیسي.** یوه دنده، یوه دننۍ دنده لکه `فایل.ولوله` یا یو ټولګی
  د یوې ازموینې لپاره نشي بدلېدای. هغه کوډ ته چې ازمویل کېږي هغه څه چې اړتیا ورته لري د برسېر
  په بڼه ورکړئ (یا د دندې ارزښت، یا د فایل پر ځای متن)، نو ازموینه ورته یو پېښه ګر ورکولای شي.

  وچلوه؛ د وتنې تر څنګ د **ازموینې** پاڼه ډلې او ازموینې د خپلو حالتونو او پیغامونو سره لیستوي، پر
  یوې کلیک ازموینې ته ځي او دوه ځله کلیک یې چلوي، د ټولو د چلولو یا ګام په ګام چلولو او د ناکامو
  د بیا چلولو تڼیو سره. چلول (F5) هم ټولې ازموینې چلوي. د ازموینې فایل وچلوئ. ډلې او د ✓ او ✗ کرښې د وتنې پاڼه کې راځي - ✓ شین او
  ✗ سور، او په لنډیز کې د تېرو شوو شمېر شین او د ناکامو شمېر سور - او د حالت پټه د وتلو کوډ
  ښيي. جوړول په شاليد کې کېږي: د حالت په پټه کې د بوختیا پټه ښکاري، او جوړول، چلول، ګام په
  ګام چلول، ژباړه، بسته کول، نوی، پرانیستل، د بېلګو لړ او د ژبې لړ تر هغه انتظار کوي چې پای
  ته ورسېږي (لیکل روان پاتې کېږي).
* **VS Code:** هر هغه فایل چې `@ازموینه` (یا `@test`) لري د **ازموینو لړ** (Test Explorer، په
  فعالیت پټه کې د کیمیا بوتل) کې د یوې ونې په بڼه راځي: **فایل ← ډله ← ازموینه**، همداسې
  موندل شوې لکه ژباړونکی یې چې مومي - هغه ازموینه چې په هېڅ ډله کې نه وي نېغ د خپل فایل لاندې
  ځي. سمونګر د هرې ازموینې تر څنګ په ګټر کې د چلولو تڼۍ ښيي. یوه ازموینه، یوه ډله، یو فایل یا
  ټول وچلوئ؛ غځونه فایل جوړوي او د ټاکل شوو ازموینو سره یې د دلیلونو په توګه چلوي (`ډله/نوم`،
  یا د ډلې نوم)، او ناکامۍ خپل پیغام په کرښه کې او د ازموینو د پایلو لید کې ښيي. د سمونګر د
  سرلیک پټې **Run Tests in This File** تڼۍ (او د دواړو سمونګرو د شرایطو مینو کې، د
  ښي-څخه-کیڼ سمونګر په ګډون) مخکښ فایل چلوي؛ **Thunder: Run All Tests** د کاري ځای ټول د
  ازموینو فایلونه چلوي. د *Debug* پروفایل ټاکل شوې ازموینې د مرستیال (debugger) لاندې، له ټولو
  ودرېدو ټکو سره، چلوي.
* **ښي-څخه-کیڼ سمونګر** (پښتو فایلونه) هماغه کوي چې متني سمونګر یې کوي - د شرایطو مینو یې هم
  Run Test at Cursor، Debug Test at Cursor، Run Tests in This File او Debug Tests in Current File لري: د هرې ازموینې او هرې
  ډلې (د هغې د `@ازموینه` په کرښه) تر څنګ په ګټر کې یوه تڼۍ - ▶ د چلولو لپاره، د چلېدو پر مهال
  یوه څرخېدونکې دایره، ✓ کله چې تېره شوه، ✗ کله چې ناکامه شوه - چې په کلیک یې چلوي؛ د ناکامې
  ازموینې لومړی پیغام د هغې د کرښې په پای کې؛ او کله چې ازموینه ناکامه شي، د هغې له کرښې لاندې
  یوه پاڼه چې هر هغه څه پکې دي چې ازموینې وویل، غشی یې ازموینې ته اشاره کوي (په × یا Escape
  تړل کېږي؛ د کرښې د پای پر پیغام کلیک، یا پر ✗ ښي کلیک، بیا یې پرانیزي). د هر چلول پایلې ښيي،
  که هر چېرې پیل شوی وي.
* **Thunder Output** (د پروګرام وتنه کله چې ګام په ګام چلېږي) د ازموینې فایل لیکنه لکه د تندر IDE
  رنګوي: ✓ شین، ✗ سور، د تېرو شوو شمېر شین او د ناکامو شمېر سور.
* **د ازموینو د پایلو لید** پښتو لیکنه له ښي څخه کیڼ ته او ښي څنډې ته برابره ښيي، لکه د تندر
  IDE، او نښې رنګه. (دا لید یو ترمینل دی چې خپل ښي-څخه-کیڼ متن نه پېژني:
  د کرښې وییونه په هغه ترتیب لیکل کېږي چې لیدل کېږي، او ترمینل هر پښتو ویی پخپله له ښي څخه کیڼ ته انځوروي.)
* **امر کرښه:** `thunderc shop_test.th && thundervm shop_test.thc`؛ د وتلو کوډ وايي چې ټول تېر
  شول که نه.

## نومونه په دواړو ژبو

نښې `@ازموینه` (`@test`؛ `@آزموینه` (له مدې سره) هم منل کېږي، او د `ی` د کیبورډ بڼې لکه هر ځای یو شان
کېږي) او `@پېښه ګر` (`@mock`) دي. انګلیسي نومونه په هره ژبه کې منل کېږي، او `thunderc --translate`
یې اړوي. د جوړښت د ډلې د پاکولو دنده `وتړه()` ده (`close()` هم کار کوي).

| انګلیسي | پښتو | | انګلیسي | پښتو |
| --- | --- | --- | --- | --- |
| `@test` | `@ازموینه` | | `@mock` | `@پېښه ګر` |
| ټولګی `test` | `ازموینه` | | ټولګی `expect` | `تمه` |
| `test.run` | `ازموینه.وچلوه` | | `expect.that` | `تمه.دا_وي` |
| `test.fail` | `ازموینه.ناکامه_کړه` | | `expect.is_true` | `تمه.رښتیا_وي` |
| `test.finish` | `ازموینه.پای_ته_ورسوه` | | `expect.is_false` | `تمه.درواغ_وي` |
| `test.runner` | `ازموینه.د_ازموینو_چلوونکی` | | `expect.equal` | `تمه.برابر` |
| `test.Runner` | `ازموینه.چلوونکی` | | `expect.not_equal` | `تمه.نابرابر` |
| `test.Result` | `ازموینه.پایله` | | `expect.near` | `تمه.نږدې` |
| `test.Mock` (ګډون) | `ازموینه.پېښه_ګر` | | `close` (پاکول) | `وتړه` |
| `called` | `وبلل_شو` | | `call_count` | `د_بلنو_شمېر` |
| `arguments_of` | `دلیلونه_یې` | | `calls` | `بلنې` |
| `forget_calls` | `بلنې_هېرې_کړه` | | `expect_called` | `تمه_د_بللو` |
| `Result`: `suite`، `name`، `failures`، `passed()` | `ډله`، `نوم`، `ناکامۍ`، `تېره_شوه()` | | `Runner`: `wants`، `counts`، `report` | `غواړي`، `شمېرې`، `راپور` |

پښتو فایل خپلې کرښې په پښتو چاپوي (`۲ تېرې شوې، ۰ ناکامې`)، له همغو ✓ او ✗ نښو سره او د ډلې
نوم د خپلو ازموینو پورته، نو د VS Code د ازموینو لړ دواړه یو شان لولي.

## له نښو مخکې

پخوا ازموینې یو پروګرام و: `"testing"` یې راوړه، د هرې ازموینې لپاره یې
`ازموینه.وچلوه("نوم"، بدنه)` او په پای کې یې `ازموینه.پای_ته_ورسوه()` بلله، او ازموینې یې په
ټولګو کې د اعلانولو له لارې په ډلو کې اچولې (`ازموینه.د_ټولګي_نوم` ټولګی موند). دا بڼه نور نه
جوړېږي - پروګرام `"testing"` نشي راوړلای (`S092`)، `ازموینه.وچلوه` اوس ډله هم اخلي، او
`ازموینه.د_ټولګي_نوم` نشته. د داسې فایل د اړولو لپاره، هغه کوډ چې ازمویل کېږي یوه کتابتون فایل
ته یوسئ، د `ازموینه.وچلوه` او `ازموینه.پای_ته_ورسوه` کرښې ړنګې کړئ، او ټولګی (یا هره دنده) په
`@ازموینه` نښه کړئ، او `@ازموینه("...")` ته هغه نوم ورکړئ چې `ازموینه.وچلوه` ته ورکړل شوی و.

**له ۰٫۷ مخکې** دا ساده دندې وې: `ازموینه` (اوس د ازموینې نښه)، `تمه` (`تمه.دا_وي`)،
`رښتیا_تمه`، `درواغ_تمه`، `برابر_تمه`، `نابرابر_تمه`، `نږدې_تمه` (`تمه.رښتیا_وي` ... `تمه.نږدې`)،
`ناکامه_کړه` (`ازموینه.ناکامه_کړه`) او `ازموینې_پای_کړه` (`ازموینه.پای_ته_ورسوه`).

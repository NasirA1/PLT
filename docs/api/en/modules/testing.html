    testing

    import "testing"

    a small test framework, written in Thunder itself (docs/testing.md)

    import "testing" and two modules are yours: test runs the tests, expect says what should be true. Write each test as a function without parameters, hand it to test.run with a name, and end the program with test.finish():

    import "testing"

    func adds_up() expect.equal(2 + 2, 4)

    test.run("adds up", adds_up) test.finish()

    Test suites are modules. Put the tests that belong together in a module of their own, and the module's name becomes the suite's: its tests are printed under it, counted under it, and can be run together by naming the suite on the command line.

    module arithmetic func adds_up() expect.equal(2 + 2, 4)

    test.run("adds up", arithmetic.adds_up) # prints "arithmetic" above " ✓ adds up"

    Every test prints one line - "✓ name" when it passed, "✗ name: what went wrong" for each expectation that failed - and test.finish() prints how many passed and failed, ending the program with exit status 1 when any failed (so a script, or the VS Code extension, can tell). Program arguments choose which tests run: "thundervm tests.thc adds" runs only the tests (or the suites) named on the command line - "suite/test" names one test of one suite - which is how VS Code's Test Explorer runs a single test or a single suite.

    Nothing here is native: this is ordinary Thunder, written to be read.

    Runs one test: the function 'body', reported under 'name'. A test passes when none of the expectations in its body failed. When 'body' belongs to a module, the test belongs to that suite: the suite's name is printed above its first test, and its tests are indented.

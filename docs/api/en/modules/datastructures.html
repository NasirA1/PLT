    import "datastructures"

    the classic data structures, written in Thunder itself (docs/datastructures.md)

    import "datastructures" and every structure below is yours (thunderc finds this file in lib/thunder next to itself, or name a directory with --module-path). Unlike sockets or graphics nothing here is native: this is ordinary Thunder, written to be read - open this file to see how a stack, a queue, a linked list, a binary search tree and a heap really work.

    Every structure is a struct with a constructor and methods: make one with its name ("var s: Stack<int> = Stack()") and use it through its methods ("s.push(1)", "s.pop()"). Most are generic: Stack<T> works for any element type T, named where the variable is declared. The tree and the heap compare their elements with <, so their elements are numbers or strings. A member whose name starts with '_' is private: only the structure's own methods may touch it - programs use the methods, never the insides.

    Taking from an empty structure is a mistake in the program and stops it, as a wrong built-in call would. Ask is_empty first.

    Linked list (singly linked)

    A chain of nodes, each holding its value and the node that follows; nothing ends the chain. Adding at the front is O(1); adding at the end and searching walk the chain, O(n). This is the textbook picture, made of a recursive struct. The nodes themselves are plain data - the list is the object that owns and works the chain.

    Heap (priority queue)

    take always returns the smallest value first, however the values arrived. The heap is a binary tree flattened into one array: the children of the node at index i sit at 2*i + 1 and 2*i + 2, and every parent is <= its children. Adding and taking are O(log n). The elements are compared with <, so they are numbers or strings.

The elements are compared with <, so they are numbers or strings. One object built on another: the ordered set owns a BinaryTree and turns every question into a tree question.

    Deque (both ends)

    A queue that is open at both ends: values join and leave at the front and at the back. Two stacks, back to back: _front holds the front half reversed (its last element is the deque's first), _back holds the rest in order. Each end is O(1); when one side runs dry it is refilled from the other, which keeps every operation O(1) on average.

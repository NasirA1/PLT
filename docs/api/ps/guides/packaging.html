    د تندر SDK لارښود یوه برخه.

    بشپړ شوی د تندر پروګرام په یوه چلېدونکې فایل اړولی شئ چې عامل سیسټم یې سیده چلوي. هغه څوک چې یې چلوي، نه IDE ته اړتیا لري، نه thundervm ته او نه .thc فایل ته — یوازې همغه یوه فایل.

    thunderc hello.th --package hello      # ./hello جوړوي (په وینډوز کې hello.exe)
./hello یو دوه                         # پخپله چلېږي؛ سیسټم.دلیلونه() = ["یو"، "دوه"]

    په IDE کې همدا کار: جوړول > د کړنلارې په بڼه بسته کړه....

    ۱. بسته څه ده#

      [ د thundervm چلېدونکې فایل، بایټ په بایټ ] [ ستاسې program.thc ] [ ۲۴ بایټه لکۍ ]

    همدومره. ELF (لینکس، مکOS) او PE (وینډوز) دواړه د انځور له پایه وروسته بایټونه پرېږدي، نو کاپي لکه اصلي پیلېږي؛ په پیل کې خپله فایل ګوري، لکۍ مومي او هغه پروګرام چلوي چې له ځان سره یې وړي. لکۍ: د پیلوځي او اندازې ۶۴-بټه کوچنی-سر شمېرې، بیا اته توري THNDPACK.

    هېڅ شی ماشین کوډ ته نه جوړېږي: د بستې دننه VM همغه بایټ کوډ ژباړي چې IDE یې چلوي، نو پروګرام سم هماغسې چلېږي، د تېروتنو پیغامونه هم لا په خپله ژبه.

    بیه یې اندازه ده: بسته = VM + ستاسې پروګرام، نو هر پروګرام چې وي، شاوخوا ۱٫۵ میګابایټه کېږي (د debug جوړښت ډېر لوی دی، ځکه thundervm بیا خپلې ډیبګ نښې له ځان سره وړي؛ -DCMAKE_BUILD_TYPE=Release وکاروئ).

    ۲. کارول#

    thunderc <source.th> --package <file> [--runtime <thundervm>] [-I <dir>]
    ټاکنه اغېزه
    --package <file>چلېدونکې فایل لیکي. په وینډوز کې .exe پخپله ورزیاتېږي.
    --runtime <file>هغه VM چې کاپي کېږي (اصلي: هغه thundervm چې د thunderc تر څنګ دی).
    -I <dir>راوړل شوي ماډیولونه او د کاپي کولو لپاره بهرني کتابتونونه هم هلته لټوي.

    --package یوازې چلېدونکې فایل لیکي، .thc نه؛ که دواړه غواړئ، -o program.thc هم ورکړئ. هغه پروګرام چې نه جوړېږي، هېڅکله نه بستېږي.

    ماډیولونه د جوړولو پر مهال حل کېږي، نو دمخه د بستې دننه دي.

    بهرني کتابتونونه: هغه پروګرام چې راوړه بهرنی کاروي، د چلولو پر مهال خپل .so / .dll / .dylib ته اړتیا لري؛ --package هر یو د چلېدونکې فایل تر څنګ کاپي کوي او وايي یې. هغه فایلونه د کړنلارې برخه دي: پوښۍ ورکړئ، نه یوازې یوه فایل. که کتابتون ونه موندل شي، بستول ناکامېږي — د داسې څه پر ځای چې د بل چا پر ماشین مات شي.

    ۳. د بستې چلول#

    هر څه چې په قومانده کې دي، پروګرام ته ځي — سیسټم.دلیلونه() (له راوړه سیسټم وروسته) یې راګرځوي — او ولوله() له عادي ننوته لولي. سیسټم.پای ته ورسوه(کوډ) د پروسې د وتلو حالت کېږي.

    د VM خپلې څو ټاکنې لا هم شته، هره یوه د --thunder- سره، نو د پروګرام له دلیلونو سره نه ګډېږي:

    ټاکنه اغېزه
    --thunder-helpدا فایل څه دی، او همدا ټاکنې
    --thunder-versionد دننه VM نسخه
    --thunder-svg <file>د ګرافیک پروګرام وروستی انځور د SVG په بڼه ساتي
    --thunder-canvasچوکاټونه د ریکارډونو په بڼه په عادي وتنه لیکي
    --thunder-statsد اجرا شمېرنې چاپوي

    د ګرافیک پروګرامونه: تندر ټاټ ته کاږي او یو کوربه یې ښيي؛ په IDE کې همغه IDE کوربه دی. بسته شوی ګرافیکي پروګرام خپله کړکۍ د یوه ښودونکي پلگ‌ان له لارې پرانيزي (د ښودونکي لارښود): بسته کول یې پخپله د پروګرام تر څنګ کاپي کوي (sdl غوره کېږي)، او کله چې پروګرام له عامل سیسټم څخه مستقیم وچلېږي، د ځان تر څنګ لومړی موندل شوی پلگ‌ان کاروي. که هېڅ پلگ‌ان ونه موندل شي، پروګرام د یوه پیغام سره درېږي چې همدې لارښود ته لار ښيي. --thunder-display <name> یو ټاکلی پلگ‌ان غوره کوي؛ --thunder-svg وروستی انځور ساتي، او --thunder-canvas هغه ریکارډونه لیکي چې یو کوربه یې کښلای شي.

    ۴. ستونزې#

    ستونزه څه وکړئ
    cannot find thundervm next to thundercنوم یې ورکړئ: --runtime path/to/thundervm
    cannot find the native library 'libx.so'هلته یې کېږدئ چې پروګرام دی، یا -I <dir> ورکړئ
    په لینکس/مکOS کې «Permission denied»thunderc د چلولو بیرغ ږدي؛ که پاتې شو: chmod +x <file>
    بسته ډېره لویه دهrelease جوړښت وکاروئ: د debug thundervm خپلې نښې له ځان سره وړي

    بسته یوه عادي فایل ده: کاپي، نوم بدلول او په PATH کې ایښودل یې سم دي — لکۍ د نوم له مخې نه، د فایل له لوستلو مومي.

    د tools/apidoc.py له لارې د اوزارو د ژبې له معلوماتو، د SDK له خپلو تبصرو او له لارښودونو جوړ شوی. د MIT جواز.
